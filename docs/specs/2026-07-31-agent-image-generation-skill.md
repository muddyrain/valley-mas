# 智能体生图能力设计

> 状态：已完成（会话体验已收敛）
> 日期：2026-07-31

## 目标

把图片创作从独立页面能力收敛为可被智能体调用的 `image.generate` 工具；图片工作台与智能体共享同一生成计划、模型目录、参考图约束、存储和审计链路，并复用同一套会话输入与生图反馈。用户可上传参考图，并通过 `/` 选择当前上下文可用的技能；被选中的技能会作为本轮的显式视觉风格，而不是要求用户记忆风格 ID 或复制提示词。

## 首期交互

- 智能体编辑器可显式绑定“图片生成”工具，并为该版本选择默认图片模型、比例和清晰度。
- 会话输入框可附带最多三张参考图；原始 data URL 仅在当次请求和生成过程存在，不写入会话消息、运行记录或审计日志。
- 输入 `/` 时展示该智能体已绑定的技能；选择后以可移除的技能标记呈现，并将其作为本轮视觉风格候选。未选择技能时不注入额外视觉风格。
- 当智能体调用 `image.generate` 时，工具复用 `AIImageGenerationService.Generate`，同步返回已转存的图片 URL 和生成记录 ID；会话将生成结果显示为图片卡片，并继续保留文字回复。
- 图片工作台默认具备生图能力，和智能体会话共用 `ConversationComposer`：两端都支持参考图预览、`/` 技能选择、Enter 发送、停止按钮及同一张图片生成阶段卡片。图片工作台的 `/` 仅列出可用的技能型视觉风格；普通视觉风格仍可在风格选择器中选择。

## 会话边界

- 两个入口在交互和能力契约上使用同一个对话框组件，但现阶段保留各自的历史实体：图片工作台使用 `AIImageConversation`，智能体使用 `AIAppConversation`。这样不会迁移或混合已有历史、版本和运行追踪。
- 图片工作台默认直接调用图片生成服务；智能体仅在版本显式绑定 `image.generate` 后获得该工具。差异只在默认工具权限，不在输入、参考图或生图反馈体验。

## 契约与边界

- 工具名固定为 `image.generate`，属于受控的模型与存储副作用；只有在智能体版本中显式绑定后才可用。
- 工具输入只允许画面描述、可选比例/清晰度和“使用本轮参考图”开关；模型由智能体版本默认配置决定，不能由模型任意切换。
- 参考图、比例、清晰度、模型能力与 owner 隔离继续由既有 `AIImageGenerationService` 校验。参考图存在时，模型必须声明 `reference_image`。
- 已绑定技能仅能由当前 owner 使用；首期仅把用户本轮显式选择的一个技能作为 `skill:<id>` 视觉风格传给图片计划器。技能仍按既有运行时规则注入给智能体，不执行其脚本。
- 一次工具调用只生成一张图。用户请求多张时，智能体可逐次调用；超过 agent 的步数或费用边界时应先说明，不伪造“已生成”。

## 非目标

- 不把画布、逐笔图层、蒙版、局部重绘或无限批量生成搬进智能体聊天。
- 不新增用户自带 Provider key、未经审核的执行型技能或自动重试。
- 不把 `/` 做成全局命令系统；首期只解决已绑定技能的显式选择与可见状态。

## 验收

1. 已绑定 `image.generate` 且配置图片模型的智能体，可通过文本请求得到与图片工作台同源的持久化图片结果。
2. 会话附图在选用支持参考图的模型后能作为生图参考；原始图片不出现在持久化消息或 AI 审计记录。
3. `/` 只能选择该智能体已绑定的技能，选中的技能会影响当次生图的风格快照。
4. 未绑定工具、未配置模型、模型不支持参考图和无权技能均有明确失败反馈。
5. 图片工作台与智能体会话在输入 `/`、附加参考图和图片生成中都展示相同的输入状态与生成反馈；两类历史仍各自可正常读取。
