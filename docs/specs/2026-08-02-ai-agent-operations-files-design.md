# 智能体后台任务、授权、检索与文件设计

> 状态：已实现，待真实模型与对象存储联调验收
> 日期：2026-08-02
> 范围：`apps/web` 智能体编辑器与私有会话、`server` AI App 运行时

## 目标

让耗时或有副作用的智能体工作可离开页面继续执行；高风险工具执行前必须由 owner 明确确认；知识库回答能配置召回方式并提供可定位的行内引用；用户文件既能作为本轮上下文，也能接收智能体生成的成果文件。

## 核心边界

- 会话消息一律先持久化，页面是否打开不改变任务生命周期。每个账号最多同时运行 3 个任务，同一会话最多运行 1 个任务；同会话后续消息严格按创建时间串行，并且每个任务只读取截至自身用户消息的历史，避免前一轮提前看到排队内容。等待中的消息在自身气泡内显示智能体等待标记，开始执行后移除。输入为空时发送按钮切换为中止按钮，输入有内容或附件时仍可提交到队列。最多保留 20 个未完成任务，不同账号不共享会导致空闲账号误排队的全局执行槽。任务运行期间按节流快照持久化模型增量输出，页面快速轮询，并在默认折叠的工具执行明细外持续展示当前回复；任务完成时先取得正式消息，再替换运行态，避免结果闪烁或短暂消失。任务状态为 `queued / running / waiting_approval / succeeded / failed / cancelled`。
- 工具策略随 AI App 版本快照保存。`auto` 可直接执行，`always` 在会话执行区创建 owner 私有确认请求；同步调试入口不得绕过确认。
- 确认记录保存工具名、风险级别、用户可读摘要和服务端参数快照。参数不返回会话页面，批准只对该任务中的同一调用指纹生效。
- 知识检索支持 `semantic` 与 `hybrid`，可配置召回数、最低相关度、关键词权重、最大上下文和是否引用。回答使用 `[n]`，页面将其渲染为可访问的行内引用。
- 会话文件支持 JPG、PNG、WebP、Markdown、TXT、PDF、JSON、CSV；图片最大 5MB，其他文件最大 2MB，每轮最多 3 个。源文件和解析文本按 owner + app + conversation 隔离。
- `file.create` 只能生成 Markdown、JSON、CSV，最大 2MB；文件同时创建私有资源与会话成果记录，页面按运行展示下载入口。
- 图片附件用于理解时直接作为多模态输入交给当前对话模型，并校验该模型具备 `vision` 能力；`image.generate` 只处理用户明确的生成或编辑图片意图，继续使用独立的图片生成模型。
- 智能体个性化由 `IDENTITY.md`、`USER.md`、`SOUL.md`、`AGENTS.md` 四段配置组成；保存会产生内部审计快照，但用户不管理版本，既有会话下一轮自动使用最新配置。
- 智能体详情页的产物 Tab 聚合该智能体全部 owner 私有成果文件和成功生成图片，跨 owner 资源不得返回。

## 数据与接口

新增数据：`ai_app_tasks`、`ai_app_tool_approvals`、`ai_app_conversation_attachments`、`ai_app_artifacts`；工具绑定增加 `approval_mode`。PostgreSQL 和 MySQL 使用同版本迁移 `202608020002`，任务增量输出字段由 `202608020003` 补充。

私有认证接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/ai/apps/:appId/conversations/:conversationId/tasks` | 创建后台任务 |
| `GET` | `/ai/apps/:appId/tasks` | 列出任务与确认请求 |
| `POST` | `/ai/apps/:appId/tasks/:taskId/cancel` | 取消任务 |
| `POST` | `/ai/apps/:appId/tasks/:taskId/approvals/:approvalId/decision` | 允许或拒绝工具 |
| `POST` | `/ai/apps/:appId/conversations/:conversationId/attachments` | 上传本轮文件 |
| `GET/DELETE` | `/ai/apps/:appId/conversations/:conversationId/attachments/:attachmentId` | 下载或删除未发送文件 |
| `GET` | `/ai/apps/:appId/outputs` | 聚合智能体 owner 私有成果文件与关联生成图片 |

检索和工具绑定沿用 `/retrieval-config` 与 `/tools`，响应增加完整配置和工具策略。

## 验收标准

1. 消息提交后立即成为持久任务；账号最多并发 3 个任务，同一会话严格串行。后续消息在自身气泡内显示等待标记，开始执行后自动消失；执行中输入为空时可中止，输入有内容时可继续提交。离开会话后继续执行，增量回复保持可见，思考与工具执行详情默认折叠；完成后由正式消息覆盖旧任务快照，不重复显示回答或残留“正在思考”。
2. `always` 工具必须停在等待确认；拒绝后工具不运行，批准后继续；同步入口返回明确的需后台执行错误。
3. 混合检索参数随版本保存，引用包含序号、文档、相关度和页码，回答中的已知 `[n]` 可交互。
4. 支持粘贴图片/文件、上传状态和纯附件消息；附件刷新后仍可预览或下载并与用户消息关联，跨 owner 读取被拒绝，文件正文或图片进入本轮上下文。
5. `file.create` 产生私有资源和成果文件卡片；格式、文件名、大小和 JSON/CSV 内容受到服务端校验。
6. 图片分析使用当前对话模型；模型不具备 `vision` 能力时阻止发送并引导切换。未启用生图工具时仍可分析图片；图片生成只在明确生成意图且已配置 `image.generate` 时执行。
7. 四份档案保存后，既有会话下一轮直接采用最新配置；详情页不出现版本管理、系统提示词、在线调试、最近运行或公开调用记录。

## 已知后续

- 当前队列是数据库轮询的单服务部署方案；多实例需要数据库级租约和心跳，避免运行中实例失联后的重复执行。
- PDF 复用知识库基础文本解析；扫描 PDF 的视觉理解仍依赖现有 PDF 多模态计划。
- 真实模型、图片服务和对象存储失败重试沿用各工具现有策略，本次不新增跨工具统一重试编排。
