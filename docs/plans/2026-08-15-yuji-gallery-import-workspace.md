# 雨迹图库稳定分页与本地批量导入工作区计划

> 状态：已实施；真实登录态下的批量导入与本地恢复验收待补。
> 日期：2026-08-15

## 问题本质

- 公共图库使用 CSS 多栏。分页追加会触发浏览器重新平衡整段内容，所以旧图片换列；资源数组没有主动重排，图片分辨率也不是根因。
- 图片导入把来源、许可和原始出处作为前置表单，但站主的新规则是普通导入默认允许预览与下载，只有平台 AI 图片保存路径需要自动标记“AI 生成”。
- 弹窗关闭会重置全部选图与处理结果，未入库工作没有恢复入口。
- AI 标题和标签是两套接口、两次看图，并且各自逐张串行、每张额外等待 300ms。十张图片同时做标题和标签至少产生二十次串行视觉请求。
- 创作室只有最近导入摘要，没有展示账号全部壁纸与头像的图片管理入口，也无法从主任务流进入编辑和删除。

## 已确认决策

### 公共图库

- 替换 CSS 多栏，使用明确的 3 / 2 / 1 列和追加稳定的列分配。
- 同一列数下分页只分配新卡片，旧卡片不得移动；跨响应式断点允许全量重排。
- 使用资源宽高比估算列高；缺失尺寸采用安全比例，不在图片加载后反复测高。
- 公共接口使用稳定总排序，至少以资源 ID 作为相同创建时间下的次级键。

### 导入数据语义

- 保留资源来源、许可和下载字段以兼容旧数据，不删除字段、不迁移历史资源。
- 新手工导入移除来源、许可和原始出处表单，自动写入允许预览与下载的兼容值；手工上传的外部 AI 图片也不自动推断来源。
- 平台 AI 图片工作台保存到资源库时继续自动标记 `ai_generated`。
- 保留资源类型、可见范围和视觉模型设置。

### 本地未导入工作区

- 使用原生 IndexedDB，不新增依赖。
- 按当前用户隔离保存图片 Blob、稳定条目 ID、选图顺序、批次设置、标题、标签、AI 元数据缓存和状态。
- 关闭弹窗、刷新或再次进入页面时恢复；中断的 AI 请求恢复为待继续或可重试。
- 成功入库的条目删除，失败和未导入条目保留；IndexedDB 不可用或配额不足时明确提示并退化为当前页面会话。
- 不创建服务端批次表、后台 worker 或跨设备同步。

### AI 元数据

- 新增统一视觉元数据接口，一次返回严格 JSON：标题、标签、实际模型和 Provider。
- 第一次执行标题或标签操作时同时生成两者；只应用本次操作对应字段，另一份结果缓存在条目中。
- 缓存边界包含图片指纹、资源类型和模型；这些输入变化后缓存失效。
- 保留两个批量 AI 操作和每项两个单独 AI 操作，不改成交互开关或自动运行。
- 批量处理使用最多 3 个并发请求并移除固定 300ms 延迟；单项错误不终止整批。

### 正式上传与顺序

- 用户点击正式导入前，所有由用户触发的 AI 操作仍在前台等待完成，不转为后台任务。
- 批次条目顺序在选图时固定；上传调度不能由 AI 完成顺序决定。
- 在现有公共资源“最新优先”语义下，上传顺序和稳定次级排序共同保证批次最终按选图顺序展示。
- 上传成功、结果确认中和失败沿用现有幂等确认语义；只清除已确认成功的本地条目。

### 创作室图片库

- 在创作室提供独立图片库，默认分页读取当前账号的全部壁纸与头像，不复用只展示少量壁纸的“最近导入”。
- 类型、可见范围和页码写入 URL；服务端负责可见范围过滤，避免前端只筛当前页。
- 复用现有资源卡片和编辑详情，支持修改标题、描述、类型、可见范围与标签，并在二次确认后永久删除。
- 图片库只保留统一批量导入入口，不恢复旧专辑侧栏或另一套单图上传流程。

## 实施步骤

### 1. 先建立失败证据

- 为图库新增分页追加回归测试：加载第二页后，第一页资源的列归属保持不变。
- 为公共资源查询补稳定排序测试，覆盖相同 `created_at` 的分页边界。
- 为批量导入新增恢复、缓存、并发上限、错误隔离和成功清理测试；先让测试在现状下失败。
- 为统一视觉元数据处理器新增请求校验、结构化响应解析、空结果和模型失败测试。

### 2. 落地追加稳定的图库列

- 抽取纯函数，根据当前列数、资源顺序、宽高比和已有列状态分配新资源。
- `YujiGallery` 持久保存当前列归属，分页时只追加；断点变化时重建。
- 用独立列容器替换 `.yuji-gallery-grid` 的 `columns`，保留现有卡片、进入动效、View Transition 和减少动画降级。
- 公共资源查询补确定性次级排序，并验证翻页无重复或遗漏。

### 3. 建立本地工作区存储边界

- 新增可注入的工作区存储接口和原生 IndexedDB 实现；数据库与对象仓库使用版本化名称。
- 保存 Blob 与结构化元数据，恢复时重新生成预览 URL，并在移除、成功或卸载时正确释放。
- 以当前登录用户 ID 隔离；登录用户变化时不得恢复另一用户的草稿。
- 处理配额、数据库不可用、旧版本升级和损坏记录，不静默覆盖可恢复数据。

### 4. 收敛导入页面和弹窗

- 从 `StudioImageImport` 删除来源、许可和原始出处表单及其前置校验。
- 保留资源类型、可见范围、模型、批量 AI 标题、批量 AI 标签和逐项操作。
- 弹窗关闭不再重置未导入条目；提供明确的移除单项与清空未导入工作区操作。
- 上传表单自动附加兼容下载策略，成功后只删除对应本地条目。

### 5. 合并 AI 视觉调用

- 服务端使用短提示词要求单一 JSON 对象，同时生成不超过 20 字的标题和 5–8 个标签。
- 统一模型解析、错误记录和 AI 用量审计；旧标题与标签接口在确认无其他调用方前保留兼容。
- Web 侧以共享 metadata 请求替换重复看图，使用并发池而不是串行 `for` 循环和固定延迟。
- 每项显示等待、处理中、已缓存、失败和可重试状态；批量完成提示基于真实成功/失败数。

### 6. 固定批量上传顺序

- 上传前读取稳定条目序号，不使用 AI 返回顺序或 Promise 完成顺序。
- 在不新增资源排序字段的前提下，按公共列表的最新优先契约安排串行上传顺序，并增加 `id` 次级排序。
- 覆盖部分失败、结果确认中、重试成功和恢复后继续上传的最终顺序。

### 7. 接入完整图片管理入口

- 新增 `/studio/images/library` 并接入创作室侧栏、首页主任务和批量导入页。
- 读取当前账号全部资源，提供类型、可见范围筛选和 24 张一页的分页。
- 复用编辑详情并补齐永久删除确认；旧 `/my-space/resources` 兼容入口跳转到新图片库。

## 验收标准

- 同一 1440px、900px 或 390px 视口连续追加至少三页，旧图片位置不变；跨列数断点后允许重排且无溢出。
- 关闭弹窗再打开、刷新页面、退出页面再返回，都能在同一浏览器和用户下恢复未导入图片及结果。
- 页面关闭时正在 AI 处理的条目恢复为可继续状态，不永久卡在“处理中”。
- 同一图片依次执行 AI 标题和 AI 标签只产生一次视觉模型调用；切换图片、类型或模型后正确失效。
- 十张图片批量处理时同时在途请求不超过 3，没有固定 300ms 人为等待，单项失败不阻塞其他项。
- 新手工导入不出现来源、许可或原始出处表单，入库后可以预览和下载；AI 工作台保存的图片仍标记 AI 生成。
- 批量图片最终展示顺序与选图顺序一致，不受图片压缩、AI 或网络完成先后影响。
- 创作室图片库可以翻阅账号全部壁纸与头像；筛选、页码可通过 URL 恢复；编辑后当前卡片同步更新，删除前必须二次确认。

## 实施状态（2026-08-15）

- 已完成公共图库追加稳定列、服务端稳定排序、原生 IndexedDB 未导入工作区、统一 AI 元数据接口、最多 3 个并发请求、固定上传顺序和默认下载策略。
- 已完成创作室完整图片库、类型与可见范围筛选、分页、编辑详情、删除确认和旧入口迁移。
- Web 定向组件/API 测试、TypeScript 类型检查、定向 Biome 检查和 Go 资源处理器测试通过；公共图库已在真实浏览器验证 1024px 双列和 329 张完整追加。
- 当前浏览器会话没有创作室登录态，因此 IndexedDB 恢复、真实 AI Provider 延迟、正式上传、图片库编辑与删除仍需使用可丢弃测试资源补做运行时验收。

## 非目标

- 不新增服务端后台导入任务、批次数据库或跨设备同步。
- 不新增图库合集、人工排序后台或第三方瀑布流/IndexedDB 依赖。
- 不删除来源与许可字段，不批量改写历史资源。
- 不让 AI 自动判断外部图片是否由 AI 生成。
