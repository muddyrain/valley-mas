# 创作者智能体工具卡实施计划

> 状态：实施中。规格见 [创作者智能体工具卡设计](../specs/2026-08-08-creator-agent-tool-cards-design.md)。

## 阶段 1：协议与生命周期

- [x] 为内部工具增加可选元数据与稳定结果信封，不破坏既有 Tool。
- [x] 增加结构化澄清请求、轮次上限、跳过/拒绝语义测试。
- [x] 为临时产物增加 owner 隔离、`expiresAt` 和清理边界。
- [x] 定义 Web 卡片联合类型和共享渲染入口。

## 阶段 2：转换工具

- [x] 实现 `image.convert`：WebP/JPG/PNG 互转、透明背景和输入限制。
- [x] 实现 `document.convert`：正常文本 PDF 尽力转换为 DOCX。
- [x] 将工具注册到 AI App 白名单、版本绑定和后台任务运行时。
- [x] 为成功、参数不足、格式不支持、owner 越权和转换失败补测试。

## 阶段 3：智能体会话卡片

- [x] 增加澄清问题卡，建议答案和自由回答都进入正式会话。
- [x] 普通对话中的必要追问也进入澄清卡；恢复时携带用户补充，且同一运行只渲染一次活动卡或最终结果。
- [x] 澄清卡作为持久时间线事件保留；回答后锁定并显示所选答案，连续编号的候选方案可显示标题与说明。
- [x] 增加转换进度、文件结果和过期状态卡。
- [x] 将工具失败结构化为可重试错误卡。
- [x] 支持刷新恢复、owner 私有下载和任务取消。
- [x] 复用现有 `ConversationComposer`、消息、附件和任务轮询，不复制状态机。

## 阶段 4：创作闭环

- [x] 增加 Markdown、PDF、DOCX 导出工具。
- [x] 增加长期保存、覆盖文档与发布博客工具。
- [x] 写操作复用现有参数指纹和 owner 确认，不开放自动发布。

## 阶段 5：验证与收口

- [x] Server 定向测试、`go test ./...` 与构建通过。
- [ ] Web 先失败后通过的定向测试、类型、静态、全量与覆盖率门禁通过。
- [ ] 当前 Chrome 会话完成澄清、转换、下载、刷新恢复、失败和确认验收。
- [x] 同步 `docs/PROJECT_GUIDE.md`。
- [ ] 完成真实转换与浏览器下载落盘验收后归档本计划。

## 当前约束

- 当前工作树已有来源未知的 AI 图片、会话组件和工作流改动；实施不得覆盖或整理这些改动。
- WebP 编解码固定使用经确认的纯 Go 依赖 `github.com/deepteams/webp@v1.2.7`；PDF 文本提取复用现有依赖，DOCX 由标准库写入，不增加第二套文档依赖。
- Web 定向测试、349 项全量测试、覆盖率与类型检查已经通过；全量静态检查仍受工作树中 48 个既有格式/规则错误和 10 个警告阻塞，本阶段涉及的 Web 文件定向检查通过，因此验证与收口阶段保持未完成。
- Chrome 已验证工具设置发布后刷新恢复、普通追问转结构化澄清、自由回答恢复同一任务、拒绝说明、Markdown 文件卡 72 小时保留、下载地址鉴权成功，以及 `blog.publish` 高风险确认后真实发布。真实图片转换受当前上游模型不可用阻塞；下载按钮已取得 HTTP 200 下载地址，但自动化未捕获系统下载落盘事件，两项保留为收口验收。
