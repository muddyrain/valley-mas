## 问题本质

- 改造前生产首页直接以 `posts[0]` 及其封面定义首屏，每发布一篇文章都会改变访客第一印象；这既违背稳定个人品牌入口，也让首页接近文章详情预告。
- 现有暖纸杂志版式适合阅读，但首屏缺少可触摸、可记忆的品牌对象；单纯放大标题、增加封面或叠加入场动画不能建立所需的触感。
- 真正困难的部分不是列表重排，而是全视口液态材质能否在真实浏览器中同时达到折射质量、指针反馈、可逆滚动和稳定帧率。因此必须先验证材质，再扩展页面。

## 目标

1. 用不依赖文章或图库更新的稳定品牌首屏，向技术同好与潜在协作者表达“技术判断与影像审美属于同一个个人世界”。
2. 通过约三屏原生滚动驱动同一张全视口“液态雨膜”，完成可逆的三幕叙事：雨痕出现、雨迹生成、纸面开启。
3. 第三幕形成“文章 / 影像”双入口，之后依次展示三篇近期文章、四至六张精选影像和作者入口。
4. 保留现有暖纸、深墨和雨蓝品牌 token，重做首页内容层与共享导航的衔接，不扩大为整站重构。
5. 为慢网、减少动画、弱设备和 WebGL 不可用场景提供立即可用的静态首页。

## 非目标

- 不建设专题精选对象、历史专题、策展数据模型或自由拖拽版式。
- 不让首页读取最新文章封面或实时图库内容作为品牌场景素材。
- 不在首屏使用巨型字标、随内容更新切换的单张文章封面、玻璃卡片、蓝紫渐变或彩虹色散。
- 不引入 React Three Fiber、Lenis、平滑滚动、滚动吸附或额外后处理框架。
- 不同步重做文章列表、文章详情、图库和关于页；这些页面只接收共享导航、token 与必要衔接修订。

## 已确认体验

### 首幕：雨痕出现

- 首次绘制立即显示静态深墨首屏、可用导航、“雨迹”普通字号署名和左下角固定宣言“在技术与影像之间，留下思考的痕迹。”。
- 纹理就绪后原位升级为无色液态雨膜；低饱和雨蓝只作为材质边缘高光，不增加新装饰性色相。
- 桌面指针在局部产生压痕、折射和惯性回弹；移动端不模拟指针，只在滑动时保留短暂压力波。

### 第二幕：雨迹生成

- 同一张雨膜随滚动被挤压、拉伸和折射，膜下三至五张固定品牌影像从模糊色块局部显影。
- 动效以厚重阻尼为主，只在折射开启时出现第一次锐利释放；宣言在材质明显变形后淡出。
- 生产实现使用站主人工确认的四张固定二次元角色纹理，不读取文章封面或实时图库内容。

### 第三幕：纸面开启

- 雨膜从中央产生裂隙并向两侧退开，形成第二次锐利释放，露出“文章 / 影像”双入口。
- 键盘焦点或指针悬停入口时，膜下只局部折射出对应预览；入口本身保持真实链接语义。
- 浅色模式揭开暖纸层，深色模式揭开深炭纸层；不使用亮屏闪烁覆盖用户主题偏好。
- 三幕正向与反向滚动完全可逆，不吸附节点；回访者可以快速滚过。

## 技术方案

### 依赖与职责

- 在进入实现时为 `apps/web` 新增 `three` 直接依赖；这是本计划唯一新增的运行依赖。
- 复用现有 `gsap`，注册 ScrollTrigger，以一个顶层 timeline 映射约三屏原生滚动进度；固定舞台本身不参与变形，只动画其子层与 shader uniform。
- 使用一个 Three 全屏画布与自定义 `ShaderMaterial` 合成雨膜、有限纹理、指针压力场和主题转场；不直接编写完整裸 WebGL 生命周期。
- 沿用当前 `gsap.context()` / cleanup 模式，不为本任务额外引入 `@gsap/react`。

### 建议代码边界

- `apps/web/src/components/yuji/YujiLiquidRainStage.tsx`：静态语义层、Canvas 容器、能力探测与降级选择。
- `apps/web/src/components/yuji/YujiLiquidRainStage.test.tsx`：静态首屏、入口、减少动画、WebGL 缺失和卸载清理契约。
- `apps/web/src/hooks/useYujiMagicScroll.ts`：ScrollTrigger 注册、三幕进度映射、导航反色和资源清理。
- `apps/web/src/hooks/useYujiMagicScroll.test.tsx`：进度、反向滚动、刷新与 cleanup 行为。
- `apps/web/src/features/yuji-home/liquidRainMaterial.ts`：Three renderer、纹理、uniform、resize、DPR 与 context lost/recovery 生命周期。
- `apps/web/src/features/yuji-home/liquidRainProgress.ts`：可独立测试的三幕进度、主题和材质参数映射。
- `apps/web/src/assets/yuji-brand/`：最终原创品牌纹理；原型目录不得成为生产运行依赖。
- `apps/web/src/pages/YujiHome/index.tsx`：组合品牌舞台、双入口和新的首页内容顺序，不承担 shader 细节。
- `apps/web/src/layouts/YujiPublicLayout.tsx`：移除导航内作者署名，消费首页舞台状态完成浅/深反色，其他公共路由保持稳定。

以上路径是实施边界而不是提前完成声明；若技术样片证明更小的模块边界足够，应优先减少文件和抽象层。

## 实施阶段

### 0. 建立失败用例与基线（已完成）

1. 记录当前首页在 390、900、1366、1440 和 1920px 的布局、请求与主题行为，确认现有未知工作树改动不与目标文件冲突。
2. 先更新 `YujiHome` 与 `YujiPublicLayout` 组件测试，明确以下新契约：首屏不显示最新文章标题/封面；静态宣言和双入口立即可用；导航不显示作者署名；文章与影像请求只影响首屏后的内容层。
3. 为纯进度映射建立单元测试，覆盖正向、反向、边界值、移动压缩和主题分支。
4. 运行 Web check、TypeScript 与定向测试，记录仓库既有失败，不把基线问题误归因于本任务。

### 1. 单屏液态雨膜技术样片（已完成）

1. 在获得本计划已记录的依赖授权后，为 `apps/web` 增加 `three`，不顺带安装其他动画或渲染框架。
2. 先实现静态语义层与能力探测，再创建一个全屏 renderer、一个材质、一个压力场和一至两张临时纹理。
3. 只验证无色雨膜厚度、雨蓝边缘高光、膜下折射、局部压痕、回弹、resize、DPR、context lost 与销毁；暂不接入三幕内容结构。
4. 在桌面 Chrome 与可用 Safari/iOS 环境记录运行证据。常用桌面设备应稳定接近 60 FPS，中端手机降质后不低于 30 FPS。
5. 样片视觉或性能未通过时，优先收缩像素比、纹理尺寸、采样次数和压力场分辨率；不得用更多滤镜掩盖材质问题。通过 owner 复验后才进入下一阶段。

### 2. 接入三幕可逆魔法滚动（已完成）

1. 注册 ScrollTrigger，一次 pin 单个全视口舞台，以约三屏滚动范围驱动一个 `ease: none` 的顶层 timeline；不平滑浏览器滚动。
2. 把滚动进度映射到雨膜形变、纹理显影、两次锐利释放、宣言淡出、主题揭示与双入口状态。
3. 保证快速滚动、反向滚动、刷新、窗口变化、字体与纹理解码后 `ScrollTrigger.refresh()` 的结果稳定。
4. 页面离开、路由返回、隐藏和卸载时暂停或销毁 rAF、事件监听、ScrollTrigger、Three 纹理和 renderer。

### 3. 重构首页内容层与共享导航（已完成）

1. 移除 `posts[0]` 作为首屏主角的结构，文章请求改为只供应三篇近期文章；影像请求供应四至六张内容层图片。
2. 第三幕组合真实的“文章 / 影像”链接与键盘焦点预览，不使用不可访问的 Canvas 点击命中区替代 DOM 链接。
3. 重排首页为双入口、三篇文章、四至六张影像和作者入口；保留各请求独立成功、失败、空状态与重试。
4. 收紧暖纸/深炭内容层排版、列表比例和留白，只使用静态裂隙或局部折射呼应首屏，不让 shader 延伸到长文和图库。
5. 共享导航只保留雨迹、文章、图库、关于、搜索，以及登录站主可见的创作室；深墨与内容层之间平滑反色，移动导航保持完整可访问性。

### 4. 原创品牌素材替换（已完成）

1. 使用四张站主人工确认的宽幅二次元角色场景，按月夜遗迹、雨中观测站、晴空花瓣和日伞近景形成明暗递进。
2. 同时准备桌面与移动裁切，预缩放到实际 GPU 使用尺寸，记录来源和可用于本站品牌展示的许可。
3. 替换技术样片中的旧内容副本，确认不同主题、DPR 和慢网下不会改变首屏布局或阻塞导航。
4. 生产代码只引用 `apps/web/src/assets/yuji-brand/`，不引用 `apps/web/prototypes/`。

### 5. 降级、验证与交付（代码与桌面 Chrome 验收完成，实机复验待办）

1. `prefers-reduced-motion`、WebGL 不可用、纹理解码失败和 context recovery 失败时直接显示静态品牌首屏、宣言和双入口。
2. 移动端压缩为两幕、限制 DPR、取消指针输入；桌面离屏后暂停持续渲染。
3. 验证浅色/深色、访客/站主、慢网/失败/空数据、键盘/触摸、快速跳过/反向滚动、resize、离开/返回。
4. 更新生产实施状态、品牌资产清单和本计划状态；只有真实浏览器证据、测试和 owner 复验都完成后才归档计划。

## 风险与退出条件

- **材质不成立**：技术样片没有真实厚度和折射触感时停止扩展页面，回到 shader/素材设计，不用更多 DOM 动画补丁掩盖。
- **移动性能不足**：先降低 DPR、纹理和压力场分辨率；仍低于门槛时移动端回退静态首屏，不牺牲导航与内容访问。
- **Safari pin/视口不稳定**：优先缩短移动滚动范围或取消移动 pin，不引入自定义平滑滚动。
- **纹理授权不清**：旧原型图片不得进入生产构建；原创资产未就绪时不宣称生产完成。
- **共享导航状态泄漏**：离开首页后必须恢复普通公共导航主题，不能把首页舞台状态带到文章或图库。
- **验证不足**：jsdom 测试不能证明 shader 视觉和 FPS；缺少真实浏览器证据时只能标记代码完成，不能标记体验验收完成。

## 完成标准

- 首页第一视口不再由最新文章或其封面决定，发布新文章不会改变品牌场景。
- 静态首屏、三幕滚动、双入口、内容层顺序、共享导航和所有降级路径均符合产品规格。
- Three/GSAP 生命周期无泄漏，桌面与移动性能达到门槛，真实浏览器验收覆盖约定视口和关键状态。
- 长期品牌素材全部为站主人工确认的固定资产，生产代码不依赖原型目录或公开内容封面。
- 相关测试、类型检查、构建、计划索引和文档链接校验通过；产品规格、品牌规范和计划状态与实际交付一致。
