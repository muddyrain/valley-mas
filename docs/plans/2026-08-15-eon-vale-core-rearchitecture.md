## 本轮边界

- 本计划把 Q1–Q165 已接受决定转成可执行顺序、保护/删除清单、测试矩阵和小提交边界。
- 本轮没有修改 Eon Vale 运行时代码，没有删除旧核心，没有升级存档，也没有声明新玩法已交付。
- 实施采用单一运行时垂直替换，不建设玩家可选或长期并存的 V2。
- 第一条退出门禁只覆盖 `12–40` 人单聚落闭环；王国、军队、战争和战后恢复已有产品合同，但必须在该门禁通过后实施。
- 不新增第三方依赖。React、Vite、PixiJS、Web Worker、Zod、Vitest 与 Playwright 继续满足当前技术需要。

## 问题本质与当前证据

- `src/simulation/core/worldSimulation.ts` 约 4,511 行，同时承担生成后初始化、生命、需求、工作、动物、聚落、经济、外交和战争，系统可以直接交叉修改同一 `WorldState`，没有唯一 Tick 写入阶段。
- `src/shared/gameTypes.ts` 约 749 行，把地形、生命、任务、聚落、王国、神力、历史和整个世界集中成共享枚举与接口；错误语义会同时渗透模拟、Worker、渲染、UI 和存档。
- `src/worker/simulation.worker.ts` 同时运行世界与压力原型两种模式，每约 `80 ms` 克隆大量数组和结构对象；协议还暴露初始 `72` 人、建设优先级与玩家规划区等已废弃玩法。
- `src/simulation/persistence/save.ts` 固定为 V13，`saveSlots.ts` 仍使用 `eon-vale.world.v6` 与旧数据库；这些数据没有新内核要求的权威事实边界、关键帧版本或安全快照清单。
- `src/render/EonValeEngine.ts` 约 3,202 行。聚落层通过 `entityId % 4` 隐藏普通实体，资源按哈希抽样；树冠采用全局前后层，职业绘制会让无武器守卫显示兵器。
- 当前工作区已有大量用户或前序任务改动，Eon Vale 的 App、模拟、渲染、Worker、测试和文档均有修改或未跟踪文件。实施前不得 `reset`、`checkout`、覆盖或批量删除；必须先由 owner 确认可恢复检查点与本次允许接管的改动范围。

## 不可违反的实施不变量

1. 任意时刻只有一个权威世界和一个可启动模拟运行时。
2. 固定 Tick 数、种子和命令序列决定结果；倍率只改变现实等待。
3. 暂停只冻结世界时间，不修改倍率、相机、工具或世界事实。
4. 缩放只改变观察投影，不改变树木、生命、活动和事件数量。
5. 动画、手持物、装备、检查器、通知和历史只读取权威事实。
6. 资源只有经过真实采集、携带和送达才进入聚落库存。
7. 玩家是神明而非城主；不恢复职业指派、建设优先级、规划区或直接军队命令。
8. V13 与旧 V6 存档命名空间断代，不增加兼容读取与迁移链。
9. 失败必须可分类、可解释和可退避；不得用随机游走、隐藏实体或后台补资源掩盖问题。
10. 四重门禁未全部通过前，不进入王国与战争实现，也不恢复第六批海洋交通。

## Tick 阶段与写权限

| 阶段 | 输入 | 唯一允许写入 | 输出 |
| --- | --- | --- | --- |
| 0. 命令边界 | 带序号玩家命令、法则变化、载入/保存请求 | 命令状态与明确玩家结果 | 接受/拒绝记录、领域命令 |
| 1. 环境与身体 | 上 Tick 世界事实 | 环境格、生命周期、健康/营养/精力计时 | 阶段变化与危险事实 |
| 2. 感知 | 位置、环境、空间索引 | 本 Tick 感知缓存 | 可见食物、危险、同伴、任务候选 |
| 3. 低频规划 | 聚落/王国事实与净缺口 | 计划、任务机会、容量 | 可领取机会与计划原因 |
| 4. 意图与预留 | 需求、感知、机会、职责 | 个体意图、预留、失败退避 | 类型化行动请求 |
| 5. 行动与战斗 | 路径、目标、动作请求 | 行动进度与待提交结果 | 移动、工作、交互、伤害结果 |
| 6. 原子提交 | 类型化结果 | 身体、库存、建筑、关系、所有权 | 成功/失败事实与事件 |
| 7. 清理与历史 | 失效目标、死亡、事件结果 | 生命周期清理、预留释放、历史、墓碑 | 不变量报告、通知候选 |
| 8. 观察发布 | 权威事实与脏集 | 只读投影缓存、序号与校验值 | Pixi 帧、领域增量、React 摘要、关键帧 |

跨阶段代码不能保存可写 `WorldState` 引用；调试构建为每个阶段运行不变量检查，生产构建至少保留便宜的边界校验与错误计数。

## 分阶段实施

### 阶段 0：保护现场并建立失败证据

- 由 owner 明确当前未提交 Eon Vale 改动的归属与恢复方式；不自动提交、不重置。
- 输出机器可检查的保护清单、删除引用清单和旧运行时入口图。
- 为固定 Tick 顺序、相同 Tick 的 `1×/8×` 校验、新世界无文明暂停开局、地形双层事实、无幽灵武器和 LOD 数量连续新增失败测试。
- 给现有地图轮廓、像素相机、导航和正式像素样板建立黄金输入/输出，防止重构误删可保留资产。

退出：新行为测试在旧代码上按预期失败；保护对象测试通过；没有执行删除。

### 阶段 1：建立 Kernel 与新世界事实

- 新建领域 ID、权威世界根、命令信封、阶段调度、写权限、不变量和稳定校验值。
- 将种子地图拆成海拔与地表生境；实现 `128/256/384`、三预设、三自然内容开关和 `2/4/6` 可定居区域确定性修复。
- 建立独立树木、野生食物、石料和普通金属的最小世界资源结构，不接聚落库存。
- 保留旧 App/Pixi 壳，只让新 Kernel 输出空文明、自然世界和诊断帧；此时不同时运行旧世界。

退出：新世界创建、种子重放、空白海洋、可定居性、暂停/倍率正交和地形编辑因果测试通过。

### 阶段 2：切换 Worker 协议与新存储命名空间

- 定义版本化命令确认、动态实体帧、地图/资源脏区、UI 摘要、检查查询和关键帧协议。
- 实现主线程背压：视觉中间帧可合并，命令结果、事件与存档确认不可丢。
- 新建严格 IndexedDB Schema、快照 Blob、原子清单、三个手动槽、每世界两个自动档、一个活动安全快照和观察元数据。
- App 启动切到新世界、默认暂停且保留浏览器倍率；删除旧世界和压力原型的产品启动路径。

退出：协议序号/重同步、暂停/倍率、保存失败不覆盖、配额清理和刷新载入 E2E 通过；旧 V13/V6 数据不会被识别。

### 阶段 3：生命生存、自治任务与聚落物流

- 接入人类持续身份、健康/营养/精力、生存阶段、感知、意图、预留、分级中断和类型化失败。
- 实现玩家单体/确定性批量投放、单居民自主建村、家庭与真实伴侣繁衍。
- 建立聚落权威库存、现场资源、食物预留/携带/进食、住宅休息、净缺口任务池与动态工作角色。
- 实现营火、帐篷、基础储存、住宅、农田、伐木点、矿点、工坊、兵营、村庄中心的真实选址、运输、施工与能力；玩家不指定建设优先级或规划区。

退出：`12–40` 人在多种子中能建村、生存、失败、解释并恢复；无重复预留、负库存、瞬移资源和无解释长期空闲。

### 阶段 4：动物、威胁、战斗与尸体

- 接入鸡、羊、牛、鹿、狼、熊物种档案、本地栖息容量、繁衍、捕食、逃跑和自然回归；鱼保持未激活档案。
- 让危险动物进入领土或感知范围即形成威胁事件；平民避让、守卫警戒/拦截、猎人按食物净缺口行动。
- 接入真实装备、职业工具、徒手/武器/动物动作、伤害、撤退、死亡、尸体、战利品和有容量处理。
- 音效与命中视觉只消费权威战斗事件。

退出：动物追逐路过聚落会触发可解释响应；死亡留下正确尸体/物品；无武器居民绝不显示武器。

### 阶段 5：聚落生命周期与完整观察

- 接入承压、饥荒、濒危、废弃、衰败、接管、毁灭和遗迹的事实派生生命周期。
- 实现居民/聚落/世界三级精确投影，森林密度、生命群、热点、战略事件与跨层迟滞。
- 重构脚点纵深、树冠拆分、遮挡轮廓、焦点揭示、稳定拾取、`M` 概览、软跟随和相机返回栈。
- 实现统一检查器、标签预算、近期通知、结构化历史、单填色层与稀疏标记组合。

退出：树木/人口跨缩放数量连续，森林中未选居民仍可读，通知可聚合定位，关闭检查器不篡改相机。

### 阶段 6：第一条切片四重门禁与旧链清理

- 运行行为、可读性、确定性和 Web 性能完整矩阵。
- 删除 `worldSimulation.ts`、旧 `gameTypes` 聚合事实、旧 Worker 协议、旧存档、旧抽样 LOD、玩家规划/建设控制及无价值兼容测试。
- 用 `rg` 与类型检查证明产品入口不能实例化旧模拟、读取旧存档或发送旧命令。
- 审计 `FULL_WORLD_VISUAL_ROLLOUT.md`、`progress.md` 和历史计划；唯一事实已迁移后删除或归档，并更新文档索引。

退出：四重门禁全部通过，旧运行时引用为零，计划状态才可从“待实施”改为“单聚落切片已交付”。

### 阶段 7：门禁后扩展

## 第一条切片硬门禁

### 行为

- 至少三个不同地形种子中，投放 `12–40` 人后可以自主建立聚落并完成进食、休息、采集、搬运、建设和繁衍。
- 至少一个资源不足种子进入可解释承压或衰败，而不是靠后台礼包存活。
- 至少一个狼/熊穿越聚落场景产生威胁、平民避让、守卫响应、战斗/撤退与解除警戒。
- 所有持续超过校准窗口的空闲、受阻和失败都有稳定原因；预留、路径和目标最终完成、取消或退避。

### 可读性

- 守卫 `equippedWeapon = none` 时基础模型和动作均不出现武器；工具、装备和携带物互斥优先级正确。
- 同一视口跨居民/聚落/世界层的树木、人口、动物与战斗聚合总数一致，切换没有哈希跳变。
- 未选居民在密林中仍有可读轮廓；选中只局部揭示，不让全图树冠透明。
- 检查器首屏能解释“现在做什么、为什么、下一步、受阻原因和预期结果”。

### 确定性

- 相同世界种子、命令日志和目标 Tick 的权威校验值在 `1×/2×/4×/8×` 完全一致。
- 保存并载入后继续到同一 Tick，与未中断运行的校验值一致。
- 渲染帧率、浏览器事件合并和 Worker 发布频率不得改变生成、行动、战斗与历史结果。

### Web 性能

- 桌面 Chrome/Edge、384×384、1,000 人＋1,000 活跃陆生动物、固定 `20 Hz`。
- 100/500/1,000 近景均要求 `FPS ≥ 60`、`P95 ≤ 25 ms`；1,000 人代表场景平均 Tick `≤ 2.5 ms`。
- 8× 30 分钟完整世界要求平均 Tick `≤ 4 ms`、Draw Calls `≤ 20`、三角形 `< 30,000`，路径队列峰值 `< 2,000` 且能够收敛。
- Chrome `usedJSHeapSize` 在 5 分钟预热后不得持续单调增长；30 分钟斜率目标 `≤ 1 MiB/min` 且最终不超过 `512 MiB`。该指标只约束可观测 JS Heap，不冒充 GPU 显存统计。

- 发现必须改变已接受玩法语义、世界法则默认值、权威事实归属或四重门禁时，停止实现并把问题恢复到 `CORE_SIMULATION_REARCHITECTURE.md` 的待决区。

- 新增仓库未使用依赖、改变浏览器目标、突破 IndexedDB 数据边界或扩大到移动端时，先取得授权。
- 四重门禁失败时只修根因，不降低门槛、不恢复哈希抽样、不用后台补资源或隐藏单位制造通过。
