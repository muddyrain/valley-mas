# 雨迹内容管理与公共浏览体验二次打磨计划

> 状态：已实施并完成自动化与公共页面浏览器验收，等待 owner 最终复验。
> 日期：2026-08-14

## 问题本质

- `/studio/articles` 已经请求全部状态的作者内容，截图中也同时存在草稿和已发布文章；真正的问题是入口与标题仍叫“文章草稿”，列表缺少封面和直接操作，导致站主无法把它识别为完整文章库。
- 当前 `DELETE /admin/blog/posts/:id` 是永久删除，会同时清理文章、封面和图文资源；本轮不虚构回收站能力，界面必须准确表达不可恢复性。
- 首页与文章页把“正在请求”“请求失败”“确实为空”混在视觉上处理。更漂亮的占位不能替代请求根因诊断，也不能无限遮住失败。
- 当前图库用固定跨列规则制造杂志节奏，但真实图片比例和风格差异较大，结果是大图、空白与序号比图片关系更醒目。
- 单图查看器已有沉浸式明暗结构，但从图库进入时缺少对象连续性，页面像突然切换到另一套界面。

## 已确认决策

### 作者文章库

- `/studio/articles` 定义为站主的“文章库”，默认显示全部状态，草稿、已发布和已归档只是筛选维度，不再把页面称为“文章草稿”。
- 使用带封面的紧凑行列表：左侧 16:10 缩略图，中间显示标题、摘要、专栏和更新时间，右侧显示状态及“编辑 / 删除”操作。
- 没有封面时显示排版化文字占位封面，并明确标记“未设置封面”；不自动抽取正文第一张图片。
- 删除采用现有永久删除语义。确认弹窗必须说明文章及关联封面会永久删除且无法恢复；删除成功后刷新当前列表，并正确处理当前页最后一项被删除的情况。

### C 端内容加载

- 请求开始后的前 `300ms` 不显示 loading，避免快速请求产生闪烁。
- 超过 `300ms` 后显示与最终内容比例接近的纸张和影像轮廓，只做低对比度呼吸，不使用三点、转圈、后台提示框或大面积空白横线。
- 数据到达后，真实内容在原位置分层淡入并轻微上移；动画不能延迟链接可用时间。
- 请求失败或请求层超时后停止显示占位，进入克制但明确的错误状态，并提供“重新试试”。确实没有公开内容时使用独立空状态。
- 首页文章与图片继续独立请求并在各自区域揭示；重点文章构图等待文章请求确定，不拿先返回的图库图片临时顶替文章封面。
- 这套状态模型覆盖首页、文章列表、文章详情和单图查看；私有创作室使用更高效的产品型加载，不照搬公共站表现。

### 图库

- 不创建合集或精选分区；用既有 `type` 明确分开壁纸与头像，筛选状态写入 URL，但不把用途筛选包装成策展关系。
- 图库改为按当前数据顺序排列的响应式瀑布流：桌面 3 列、笔记本 2 列、手机 1 列，保留图片原始比例并统一间距。
- 序号退为弱信息，标题与必要元数据贴近图片；不再通过任意放大某几张图片制造策展关系。
- 图片首次进入视口时轻微错峰浮现，悬停只做克制缩放和信息显现。

### 单图查看

- 优先使用浏览器原生 View Transition 能力，让图库缩略图与详情主图以资源 ID 建立共享图片过渡。
- 主图只完成一次轻微缩放和清晰度过渡，右侧标题、作者与规格信息依次淡入；返回图库时在可行路径上反向衔接。
- 不支持共享过渡的浏览器退化为普通淡入，不阻塞导航；`prefers-reduced-motion: reduce` 下立即显示最终状态。
- 继续复用仓库现有 GSAP，不新增第三方依赖，不修改依赖清单。

## 实施顺序

### 1. 先建立行为证据

- 在浏览器中记录首页和 `/articles` 的公开文章请求、响应状态、耗时与响应体，分别覆盖访客态和站主态。
- 核对公开文章的 `status`、`visibility`、`postType` 和分页条件，确认数据缺失发生在服务端筛选、请求失败还是前端状态渲染。
- 先补最小回归测试，再修复确认的根因；不预设一定是前端样式问题。

### 2. 重做作者文章库

- 更新创作室侧栏、页面标题、浏览器标题和全局搜索中的“文章草稿”为“文章库”；创作室首页仍保留“最近草稿”，但“查看全部”明确进入文章库。
- 为 `StudioArticles` 增加封面缩略图、无封面占位、更新时间和独立操作区，保证操作按钮不会误触整行导航。
- 复用现有 `deletePost` API 与 Dialog 组件实现永久删除确认，删除期间禁用重复提交，成功后刷新并校正分页，失败时保留当前项并给出反馈。
- 保持现有文章类型兼容：`blog` 与 `image_text` 仍统一进入文章库，并进入各自现有编辑路径。

### 3. 收敛公共内容状态机

- 抽取公共站专用的延迟显影状态边界，明确 `idle / delayed-loading / success / empty / error`，使用 fake timers 测试 `300ms` 阈值和卸载清理。
- 首页文章与图片分别接入状态边界；已成功的区域不因另一个请求失败而回退。
- `/articles` 移除通用 `BoxLoadingOverlay`，使用文章列表最终结构的低对比度轮廓；文章详情与单图查看使用各自最终构图轮廓。
- 错误态提供原地重试，空状态只在请求成功且列表确实为空时出现。

### 4. 将图库改为真实瀑布流

- 移除当前按位置分配大中小跨列的模板，不改变接口与资源排序契约。
- 使用稳定的 3 / 2 / 1 列响应式布局，卡片保持原图比例并避免跨列断裂；缺少尺寸元数据时使用安全比例兜底。
- 收紧纵向空白、弱化编号，保持来源、许可和单图链接可访问。
- 复用公共动效入口为图片增加一次性错峰揭示；减少动画模式下不设置隐藏初态。

### 5. 增加单图共享过渡

- 为图库图片和详情主图提供基于资源 ID 的稳定 transition name，并通过渐进增强包装路由跳转。
- 为无原生 View Transition 的环境提供 GSAP 进入时间线，集中管理主图与信息栏的顺序、清理和取消。
- 图片加载失败、详情请求失败、浏览器后退和直接打开详情 URL 时都必须保持可用，不依赖前一页状态。

## 测试顺序

1. `StudioArticles`：默认全部状态、封面与无封面占位、正确编辑路径、永久删除确认、API 成功/失败、删除后分页校正。
2. 公共显影状态：`300ms` 前无闪烁、阈值后轮廓出现、成功/空/错误互斥、重试和卸载清理。
3. `YujiHome`：文章与图片独立完成，资源先返回时不会临时占据文章封面，公开文章失败不会永久停留在占位态。
4. `YujiArticles` 与文章详情：移除通用三点 loading，加载、空、错误和重试状态正确。
5. `YujiGallery`：没有合集语义，壁纸与头像按 URL 用途筛选分开显示，各视图内资源只出现一次且顺序不变。
6. `YujiImage`：直接访问、共享过渡支持/降级、减少动画和错误状态。

## 浏览器验收

- 公共页面视口：390px、900px、1366px、1440px、1920px；创作室重点验证 900px、1366px 和 1440px。
- 使用真实网络请求验证快速响应、慢速响应、请求失败、空数据和部分成功，不只使用静态 mock 截图。
- 文章库在 177 篇规模下仍可快速扫描；长标题、无摘要、无封面、草稿、已发布和图文文章不破坏行高与操作区。
- 永久删除只使用专门创建的可丢弃草稿验收，不能删除已有真实内容。
- 图库的壁纸与头像视图在真实横图、竖图和方图混排下保持 3 / 2 / 1 列节奏，无巨大空洞、裁切或横向溢出；刷新与浏览器回退保留用途筛选。
- 单图过渡覆盖图库点击、浏览器返回、直接打开 URL、无原生支持和减少动画模式。

## 非目标

- 不新增回收站、软删除字段、恢复接口或自动清理任务。
- 不新增主题合集数据模型、后台策展能力或图片风格分类。
- 不自动从文章正文抽取封面。
- 不改变资源来源、许可和下载契约。
- 不新增动画或瀑布流依赖，不整理或覆盖现有 `pnpm-lock.yaml` 改动。

- 已完成：作者文章库命名与紧凑封面列表、永久删除确认、公共站 300ms 延迟显影与错误重试、响应式列式瀑布流、单图共享过渡和相关回归测试。
- 已完成：使用真实公开文章与图片数据在 1440px、900px 和 390px 视口验收首页、文章列表、文章详情、图库与单图查看；图库分别呈现 3 / 2 / 1 列，无横向溢出，浏览器控制台无错误或警告。
- 已完成反馈修订：首页重点文章不再被先返回的图库图片临时顶替封面，首页影像区改为无重叠的主图加双副图网格；公共路由同步进入公共壳，不再显示私有应用的全页加载卡；图库按 URL 明确分开壁纸与头像。
- 已完成反馈修订：文章页专栏改为单行横向轨道并收紧首屏与文章条目；图库移除脚本测高网格，改为桌面 3 列、笔记本 2 列、手机 1 列的标准列式瀑布。

- 未执行破坏性验收：没有为验证永久删除而删除现有真实文章；成功、失败和分页校正由组件测试覆盖。
