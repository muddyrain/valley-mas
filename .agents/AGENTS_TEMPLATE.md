# AGENTS 模板（AI Coding 约束复用版）

> 用于新建/重写子项目 `AGENTS.md` 时直接套用，再按目标项目命令替换占位符。

## AI 任务最小上下文入口

- `AGENTS.md` -> `apps/<project>/AGENTS.md` -> `apps/<project>/README.md` -> `apps/<project>/<primary-entry>`。
- 文档治理/约束变更任务：继续读取 `docs/README.md` -> `docs/PROJECT_GUIDE.md` -> `docs/HARNESS_ENGINEERING.md`。

## AI Coding 约束（行为改动默认顺序）

- 行为改动（状态变更、权限分支、请求参数/响应映射、列表筛选分页、存储写入、关键交互）默认按以下顺序执行：
  1. 先补齐或更新对应测试（优先同目录就近测试）。
  2. 先跑受影响测试，确认先出现可观测失败。
  3. 实现改动。
  4. 再跑受影响测试并确认通过。
- 仅文案、纯样式且无可观测行为边界的改动可提豁免，但需在交付说明写明“未测原因 + 替代验证”。

## 本地 Preflight 约束（AI Coding 默认前置）

- 行为改动进入实现前先跑：
  1. 静态检查：`pnpm --filter @valley/<package> check`（或该子项目等价脚本）。
  2. 类型检查：`pnpm --filter @valley/<package> exec tsc --noEmit`（或该子项目类型命令）。
  3. 受影响行为测试：优先最小范围，要求先失败再改。
- 触及共享边界（路由/权限/共享库/API 封装）后补充对应增量验证。

## 校验要求 / 提测前最小门禁

- 行为类高风险改动提测前至少确保：
  1. 静态检查通过。
  2. 类型检查通过。
  3. 受影响行为测试通过（无测试脚本时说明替代验证方案）。
  4. 跨层联动涉及前后端/配置时同步校验契约与 `.env.example`。

## 复用要点

- 该模板只保留“行为边界 + 验证闭环”三件事，不强制约束项目文风。
- 新建 AGENTS 时建议保留以下替换变量：
  - `<package>`：当前子项目包名，如 `@valley/web`、`@valley/admin`。
  - “受影响行为测试”：按脚本能力映射为 `test`、`exec vitest run`、`go test ./...` 等。
- 其余项目特有约束（设计系统、测试脚本、验收标准）放在项目 AGENTS 的独有段落里补充。
- 对齐具体项目时，可直接参照 [示例清单](./AGENTS_TEMPLATE_EXAMPLES.md)（web/admin/server）。

## 新建 AGENTS 速查清单（3 分钟版）

- 基础信息
  - 写清项目边界、端口、启动方式和关键入口路径（如 `src/App.tsx`、`src/main.tsx`、`cmd/server/main.go`）。
  - 写清技术栈与关键外部依赖边界（UI、状态、测试框架、构建方式）。
- 约束模块
  - 先粘贴 `AGENTS_TEMPLATE.md` 的最小上下文入口和三大约束段落（行为顺序、Preflight、提测门禁）。
  - 补齐项目特有约束：设计系统、共享边界、关键文案/可访问性要求。
- 验证闭环
  - 列出“行为改动最小测试入口”与“无脚本替代验证方案”。
  - 在“提测前最小门禁”里写清静态检查、类型检查、行为测试、联动校验脚本。
- 契约同步
  - 涉及路由、模型、权限、AI 接口时，补写联动校验（前端调用方/服务端路由/`env` 示例）。
  - 若更新长期计划入口、验收标准、数据模型，补充相应计划同步说明。
