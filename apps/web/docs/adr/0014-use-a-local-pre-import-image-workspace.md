# 图片批量导入使用本地未入库工作区

状态：已接受，待实施。

批量导入是站主在资源入库前整理一组本地图片的任务，不是需要服务端长期运行的后台作业。当前弹窗关闭后会清空文件和处理结果；AI 标题与标签又分别逐张串行调用视觉模型，并在每张后额外等待 300ms。十张图片同时执行标题和标签时至少产生二十次串行视觉请求，等待主要来自重复看图和串行调度，而不是 UI 动画。

导入弹窗保留现有资源类型、可见范围、批量 AI 标题、批量 AI 标签，以及每项单独生成标题和标签的操作。来源、许可和原始出处表单从新导入流程移除：普通手工上传不标记来源，默认允许预览与下载；平台 AI 图片工作台保存的资源自动标记为 AI 生成。数据库和 API 的来源、许可与下载字段继续保留以兼容旧资源，不执行历史数据迁移，也不尝试识别手工上传的外部 AI 图片。

尚未入库的图片 Blob、选图顺序、资源类型、可见范围、模型、标题、标签、AI 缓存和逐项状态保存在按当前用户隔离的原生 IndexedDB 工作区。关闭弹窗、刷新或之后再次进入创作室时恢复工作区；页面关闭时尚未完成的网络请求恢复为可继续或可重试，不伪装成仍在运行。成功入库的条目从工作区删除，失败或未导入条目继续保留。该工作区只属于当前浏览器，不跨设备同步，不新增服务端批次模型或后台 worker。

标题和标签统一由一个视觉元数据接口一次返回严格 JSON。第一次对某张图片执行任一 AI 操作时同时生成标题与标签，界面只应用当前操作请求的字段，另一份结果以图片指纹、资源类型和模型作为缓存边界保存；之后执行另一项操作直接使用缓存。批量处理使用有限并发并移除固定 300ms 延迟，单项失败不清空其他结果。正式上传仍在用户点击导入后等待完成，并按照固定的选图顺序产生可预测的资源顺序。

这个决定优先减少重复视觉调用和意外丢失，不把导入前草稿扩张成服务端资产管理系统。IndexedDB 不可用或配额不足时必须明确提示，并至少保留当前页面会话，不得静默丢弃用户已选文件。
