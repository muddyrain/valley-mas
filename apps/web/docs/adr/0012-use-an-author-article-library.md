# 创作室使用统一作者文章库

状态：已接受并实施。

`/studio/articles` 是站主管理自己全部文章的入口，不是只处理未发布内容的草稿箱。页面默认展示所有状态，草稿、已发布和已归档只作为筛选条件；`blog` 与 `image_text` 继续遵循现有兼容边界，在产品语言中统一称为文章并进入各自编辑路径。创作室首页可以保留“最近草稿”，但其“查看全部”必须明确指向文章库。

文章库使用适合大量内容扫描的紧凑行列表，而不是大封面卡片网格。每行包含 16:10 封面、标题、摘要、专栏、更新时间、状态以及编辑和删除操作。没有封面时显示明确的排版化占位并标记“未设置封面”，不从正文自动抽取可能语义错误或授权不明的图片。

删除沿用现有永久删除接口，不新增回收站或软删除数据模型。界面必须在执行前明确说明文章及关联封面会永久删除且无法恢复，删除期间阻止重复提交，失败时保留当前列表项，成功后刷新当前页并校正分页。永久删除不能藏在整行点击中，也不能通过模糊的“移除”文案弱化后果。

这项决定优先解决信息架构和操作可发现性，同时保持当前服务端契约不变。未来只有在明确需要恢复窗口、保留期限和自动清理规则时，才单独设计回收站能力。
