# 没有显式策展数据时不推断图库合集

状态：已接受并实施。

公共图库只有在存在独立合集数据、标题、引言和站主明确选择的图片关系时，才把“主题合集”作为浏览单元。资源的 `type` 只描述既有资源用途，`tags` 只承担检索元数据；两者都不能被自动转换成“人物与角色”“风景与想象”等合集。`type` 可以作为明确的用途筛选，避免头像和壁纸混排，但筛选本身不表达策展关系。

在正式策展数据模型落地前，`/gallery` 默认展示壁纸，并通过 `/gallery?type=avatar` 切换到头像；每个用途视图内部仍是单层时间流。页面按现有数据顺序采用无需脚本测高的响应式列式瀑布布局：桌面三列、笔记本两列、手机一列，保留原始图片比例并使用统一间距；不通过任意放大某些图片、醒目序号或大面积空白暗示不存在的策展关系。页面不显示虚构的合集标题、合集数量或合集查询状态；单图仍进入现有沉浸查看器。

这一决定优先保证界面语义与真实数据一致，并缩短当前视觉优化范围，不在本轮新增数据库、接口或后台策展能力。未来显式合集模型落地后，可以在不改变单图数据与查看器契约的前提下恢复合集入口。

2026-08-15 补充：本决策中的“列式瀑布布局”只约束无合集时的单层影像墙语义，不再约束具体 CSS 实现。CSS 多栏会在分页追加时重新平衡旧卡片，相关实现选择由 [`0013-use-append-stable-gallery-lanes.md`](./0013-use-append-stable-gallery-lanes.md) 取代；本决策关于“不推断合集”的部分继续有效。
