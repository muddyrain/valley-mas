# 文章配套包功能设计

> 状态：已实施，待生产配置与上线验收
> 日期：2026-08-26
> 范围：`apps/web`、`server`、TOS 对象存储配置

## 1. 目标与边界

文章可以携带一个用于分发源码、配置或素材的 ZIP 配套包。公开文章的访客无需登录即可查看安全预览并下载原包；草稿、私密文章和待发布配套包仅站主可访问。配套包的替换与移除服从文章现有的草稿—发布边界，不绕过发布确认。

本功能不提供在线运行环境、包内全文搜索、AI 阅读、恶意软件扫描、配套包版本历史、多附件列表或独立许可表单。允许下载不等于允许复用；复用权利只来自包内 `LICENSE` 或文章正文。

## 2. 产品契约

### 2.1 数量与展示

- 每篇文章至多有一个当前配套包。
- 不填写独立名称、描述或版本号；界面显示原文件名、文件大小、文件数和更新时间。
- 文章正文末尾、标签与相关文章之前显示紧凑的“文章配套包”区块。
- 详情页直接提供下载；“展开预览”在文章末尾原地展开文件树与内容，不切换页面。

### 2.2 发布语义

| 文章状态 | 配套包变更 | 公共站结果 |
| --- | --- | --- |
| 新草稿 | 上传并绑定配套包 | 仅站主可见 |
| 已发布文章 | 上传新包 | 旧包继续在线，新包作为待发布配套包 |
| 已发布文章 | 移除配套包 | 旧包继续在线，移除作为草稿变更 |
| 再次发布 | 替换或移除已就绪 | 在同一数据库事务中切换当前引用 |
| 放弃配套包变更 | 取消替换或移除 | 继续使用旧包或无包状态 |

上传中、确认失败或尚未确认的包不能随文章发布，但不阻止保存草稿。发布完成后才异步清理失去引用的旧对象；发布失败时旧包必须继续可用。

### 2.3 权限矩阵

| 内容状态 | 匿名访客 | 站主 |
| --- | --- | --- |
| 已发布且公开 | 查看当前包清单、预览、下载 | 同匿名访客 |
| 现有 `shared` 兼容范围 | 服从文章现有访问规则 | 允许 |
| 私密文章或草稿 | 拒绝 | 允许访问编辑态有效包 |
| 待发布或临时配套包 | 拒绝 | 仅通过创作室接口允许 |

公共文章接口始终返回当前已发布包，不能因为站主已登录而泄露待发布包。创作室使用独立的站主接口读取编辑态有效包。

## 3. 生命周期

配套包是不可变文件记录；替换会创建新记录，不覆盖已有对象。

```text
uploading → ready → bound → unreferenced → deleting → deleted
     └────────→ failed ───────────────────────────────┘
```

- `uploading`：已签发上传凭证，私有临时对象尚未确认。
- `ready`：临时对象和 ZIP 清单校验完成，可以绑定文章。
- `bound`：对象已提升到持久私有前缀，并被未发布文章、已发布文章当前引用或已发布文章草稿引用。
- `failed`：确认失败；不能绑定，等待清理。
- `unreferenced`：替换、移除或永久删除文章后不再被引用。

上传凭证有效 15 分钟。未绑定临时包保留 24 小时；服务端清理任务删除过期记录和对象，TOS 只对临时前缀配置更长的生命周期规则作为遗漏兜底。绑定时通过 TOS 服务端复制把已确认对象提升到持久私有前缀，数据库提交后再删除临时对象，避免生命周期规则误删已绑定包。清理必须可重试，并在删除对象成功后再删除记录。

## 4. 数据模型

新增 `ArticlePackage`，至少保存：

- `id`、`owner_id`、可空的 `post_id`
- `status`、`storage_key`、`original_file_name`
- 原包 `size`、`sha256`、对象 `etag`
- `entry_count`、声明的 `expanded_size`
- 受信任的 `manifest` JSON
- `expires_at`、`delete_after`、`confirmed_at`、`created_at`、`updated_at`

`Post` 新增可空的 `article_package_id`，只表示当前文章状态引用的包；文章累计配套包下载次数保存在 `Post`，替换包不重置。

已发布文章的待发布变更继续进入现有 `draft_data`，但必须使用显式动作避免旧草稿缺少新字段时被解释为“移除”：

- `keep`：保持当前包。
- `replace`：使用指定的已就绪、同站主配套包。
- `remove`：发布时清空当前包。

PostgreSQL 和 MySQL 分别新增版本化迁移；既有文章和既有草稿无需回填，默认 `keep` / 无配套包。

## 5. 上传与确认协议

1. 创作室提交文件名和大小，请求上传凭证。
2. 服务端验证站主身份、`.zip` 扩展名和不超过 64MB，创建 `uploading` 记录，并签发限定对象键与 15 分钟有效期的私有 PUT 地址。
3. 浏览器直接上传 TOS，展示真实进度；API 服务不转发文件主体。
4. 浏览器调用确认接口。服务端对记录加所有者与状态约束，以带 ETag 条件的固定大小范围流读取对象并计算大小与 SHA-256，不把整包载入内存。
5. 服务端解析 ZIP、生成清单并原子更新为 `ready`。重复确认同一个已就绪记录直接返回相同结果。
6. 保存文章时先把已确认对象服务端复制到持久私有键并校验结果，再在数据库事务中绑定配套包；事务提交后删除临时对象。首次保存前的临时包 ID 同步进入按用户隔离的本地文章草稿，刷新后可在 24 小时内恢复。

确认失败不得改变文章或旧配套包。并发上传使用不同配套包 ID；只有编辑器当前明确选择的 ID 可以进入保存请求，较早完成的请求不能覆盖较新的选择。

TOS CORS 只允许生产与明确的本地开发来源执行所需的 `PUT`，不开放通配来源或读取私有对象。最终确认仍以服务端读取到的实际对象为准，不信任浏览器提交的大小、哈希或清单。

当前 `valley-resources` 桶已追加文章配套包专用规则：仅允许 `http://localhost:5174`、`http://127.0.0.1:5174` 与 `https://www.muddyrain.top` 发起 `PUT`，请求头仅允许 `Content-Type` 与 `x-tos-acl`，预检缓存 3600 秒。修改规则时必须保留桶内其他业务已有规则，并用真实页面 Origin 复验；Origin 不得带路径或末尾 `/`。

## 6. ZIP 校验

### 6.1 整包限制

- 原始 ZIP 不超过 64MB。
- 条目总数不超过 2048，目录也计入。
- 中央目录声明的解压总量不超过 128MB。
- 单条规范化路径不超过 512 字节，且必须是有效 UTF-8。

### 6.2 必须拒绝

- 无效、空或加密 ZIP。
- 绝对路径、反斜杠、空字节、`.` / `..`、路径穿越或规范化前后不一致的路径。
- 符号链接和规范化后重复的路径。
- 超出大小、数量或路径限制的归档。

未知普通文件允许保留在原包中，但不因此获得预览能力。系统不声称执行恶意软件扫描；站主仍对公开分发内容负责。

## 7. 清单与范围预览

清单条目至少包含真实路径、目录标识、压缩方式、压缩与解压大小、CRC32、数据偏移和预览类型。偏移只能由服务端在确认时从本地 ZIP 计算，预览接口不得接受客户端提供的偏移或长度。

预览请求执行以下步骤：

1. 按文章与访问者判断权限，并选取公共当前包或创作室编辑态有效包。
2. 通过真实路径精确查找清单条目。
3. 使用对象 ETag 条件和清单中的偏移，从 TOS 读取该条目的压缩字节范围。
4. 只处理 ZIP Store / Deflate；使用输出限制器流式解压并校验大小与 CRC32。
5. 以安全的响应类型返回；任何清单、对象或校验不一致都停止预览，不回退为整包下载。

### 7.1 首版白名单

| 类型 | 单文件限制 | 行为 |
| --- | --- | --- |
| UTF-8 文本与源码 | 1MB | 纯文本或代码视图 |
| Markdown | 1MB | 安全渲染与源码切换 |
| JPG、PNG、WebP | 10MB | 校验实际 MIME 后显示 |
| HTML、SVG、XML | 1MB | 仅源码，不作为活动文档或图片执行 |
| GIF、PDF、音视频、未知二进制 | — | 只显示名称、类型和大小 |

Markdown 使用独立安全渲染器：原始 HTML 必须转义；外部活动内容不加载；包内相对图片只解析到同一配套包内、仍满足图片白名单的真实路径。不能直接复用当前允许原始 HTML 的文章 Markdown 输出。

文本与图片响应设置 `X-Content-Type-Options: nosniff` 和收紧的 Content Security Policy。服务端与客户端都不创建可执行 HTML、SVG 或脚本上下文。

## 8. 接口边界

接口名称可在实现时按现有 router 约定微调，但职责保持如下：

### 8.1 创作室

- `POST /admin/blog/article-packages/upload-ticket`：创建临时记录并返回私有上传地址。
- `POST /admin/blog/article-packages/:id/confirm`：幂等确认、校验并返回配套包元数据。
- `GET /admin/blog/posts/:id/article-package`：返回编辑态有效包与清单。
- `GET /admin/blog/posts/:id/article-package/file?path=...`：站主预览待发布文件。
- 文章创建/更新请求增加配套包 ID 或 `keep | replace | remove` 动作。

### 8.2 公共站

- `GET /public/blog/posts/id/:id/article-package`：按文章权限返回当前包元数据与清单。
- `GET /public/blog/posts/id/:id/article-package/file?path=...`：返回单个安全预览文件。
- `POST /public/blog/posts/id/:id/article-package/download`：鉴权后累计文章下载次数，并返回约 5 分钟有效、带原文件名下载响应头的预签名地址。

下载计数代表成功签发地址，不声称文件已完整传输；匿名下载不新增访客历史、原始 IP 或用户画像。

## 9. 界面状态

### 9.1 创作室

内容画布增加一个配套包区块，覆盖：无配套包、上传中、确认中、已就绪、失败、待替换和待移除。站主可以上传、取消上传、重试确认、预览、替换或移除；发布检查显示最终将生效的文件名与状态。

若所选新包未就绪，发布按钮说明原因并阻止发布；站主可取消本次包变更后继续发布。旧线上包不会因新包上传失败而消失。

### 9.2 公共详情与内联预览

详情区块显示原文件名、大小、文件数、更新时间、“展开预览”和“下载配套包”。同时提示“复用许可以包内 LICENSE 或文章说明为准”。

文章详情内联预览在桌面使用文件树与内容双栏，移动端先选择文件再显示内容；选择同步到文章详情的 `?file=`。根目录或唯一顶层目录中的 `README.md` 优先打开；没有 README 时只显示文件树。若全部条目共享一个顶层目录，界面可折叠该层，但真实路径、下载包和深链接不改变。包替换后失效路径回退到新包首页，不展示旧内容。

内联预览沿用文章的安静阅读层，不引入持续 WebGL；文件预览响应设置 `X-Robots-Tag: noindex`。包内内容不进入站内搜索、文章 AI 问答、RSS 或站点地图。

## 10. 删除、统计与一致性

- 重新发布时，在数据库事务内切换 `article_package_id`、清理草稿动作并保留文章累计下载次数。
- 事务提交后把旧包标记为无引用，停止签发新的预览与下载地址；替换场景至少等待现有 5 分钟下载地址失效并留出缓冲后再删除对象，删除失败由清理任务重试。这段宽限期不构成可访问的版本历史。
- 永久删除文章时一并回收当前包、待发布包和仍绑定该文章的记录。
- 删除临时包、取消替换或上传失败不能删除仍被当前文章或其他草稿引用的对象。
- 持久对象键在绑定后不可变且归属站主；绑定、预览、下载、删除都同时校验所有者和文章引用关系。

## 11. 验证矩阵

### 服务端自动化

- ZIP 校验：正常 Store / Deflate、64MB 边界、2048 条目、128MB 声明解压量、UTF-8 与 512 字节路径。
- 攻击样本：路径穿越、绝对路径、反斜杠、空字节、重复路径、符号链接、加密包和伪造大小。
- 范围读取：正确偏移、输出上限、CRC / ETag 不一致、未知压缩方式和请求取消。
- 权限：匿名公开、私密拒绝、站主草稿、公共接口不返回待发布包。
- 状态：确认幂等、并发选择、替换/移除发布原子性、发布失败保留旧包、过期回收重试。
- PostgreSQL / MySQL 迁移及文章旧草稿兼容。

### Web 自动化

- 上传状态 resolver、发布阻断与取消变更。
- 文件树单根折叠、README 默认项、`?file=` 刷新与失效回退。
- 安全类型与不支持类型展示、Markdown 原始 HTML 不执行。
- 公共详情、创作室编辑态和错误重试的可观察状态。

### 运行时证据

- 真实 TOS CORS 直传、进度、确认、预览和签名下载。
- 匿名公开下载、站主私密预览，以及文章替换、移除和重新发布路径。
- 390px、900px、1440px 下详情区块与内联预览无溢出、文件树可操作。
- 过期签名、对象删除、网络中断和刷新恢复不暴露旧包或形成永久 loading。

## 12. 上线顺序与回滚

1. 保持已配置的受限 TOS CORS，并配置临时对象生命周期规则。
2. 部署双数据库迁移、私有对象能力、清理任务和服务端接口。
3. 部署创作室上传与发布状态，再部署公共详情和内联预览。
4. 完成真实 TOS、匿名权限和移动端验收后开放入口。

该功能不迁移旧文章，也不改变图片资源的公开 URL 策略。回滚时可以隐藏 Web 入口并停用新路由，保留可空字段与私有对象记录等待安全清理；不得通过回滚迁移直接删除仍有引用的对象或统计数据。
