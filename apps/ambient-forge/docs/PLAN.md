# Ambient Forge v0.3 计划

## 目标

证明一个核心体验：用户刷新页面后直接以固定主角“岚”的第三人称视角进入持续运转的精致小镇；主角可在连续地面、道路和街区中移动、奔跑、跳跃，并可按 F 上下空车驾驶。其他居民始终保持 NPC 身份，不再被玩家附身。原有昼夜、天气、音乐响应与摄影能力继续作为世界氛围层，但只从 Esc 暂停菜单进入，不再提供全镇俯瞰、地标巡游或自动抢占控制权的事件流程。

## 非目标

- 不做多场景平台、编辑器、商城、登录、服务端、真实天气、定位或系统音频捕获。
- 不做 MP4、GIF、离线逐帧渲染、物理流体、写实雪地形变或可编辑地形。
- v0.3 不做建筑室内、生命值、战斗、复杂事故物理、联机或世界状态持久化；刷新后还原初始世界。
- v0.3 不把移动端作为验收范围；只接入免登录、免付费、授权清晰且已记录来源的 CC0 角色/环境资产。
- 当前固定主角阶段不做居民附身、全镇俯瞰、自动事件接力、抢占有人车辆、警察或犯罪系统；历史事件资产保留在源码中，但不进入默认运行循环。

## 技术与体验约束

- React 19 + Vite 6 + TypeScript + 直接 Three.js；Web Audio 负责本地音乐分析与程序化环境声。
- 场景只消费经过 clamp 和平滑的 `AmbientInputs`，不依赖 UI、媒体元素或未来天气来源。
- 桌面优先；支持 reduced-motion、页面隐藏降频和完整资源回收。
- 导出只提供浏览器实际支持的 10 秒 WebM；无音频时明确说明。

## v0.3 可玩小镇垂直切片

本阶段把“只能观看的浮空群岛页面”转为可直接游玩的连续地面小镇。旧浮岛装配代码暂时保留但不进入默认场景，避免在首个可玩闭环中同时维护两套空间尺度。

- [x] 连续地面与道路：中心广场、住宅街、港口工坊、花园温室通过主环路、支路、人行道、斑马线和停车点连接。
- [x] 可见世界边界：使用悬崖边缘、封闭隧道、建筑外墙、绿植和花坛表达边界；角色与车辆使用独立碰撞半径，不穿过建筑与大型绿植。
- [x] 控制权闭环：上帝视角点击模型或居民菜单接管角色；WASD 移动、Shift 奔跑、Space 跳跃、Esc 释放控制；切换或释放后原居民恢复自主路线。
- [x] 车辆闭环：居民靠近车辆后按 F 上车，使用 WASD 驾驶、Space 刹车、F 下车；镜头保持车辆位于画面中下方并朝前观察，速度影响视野角。
- [x] 车辆善后：正常下车后车辆留在原位；驾驶中直接释放控制会安排车辆回到最近停车点，居民恢复原有活动。
- [x] 精细角色资产：接入 Kenney CC0 统一骨骼角色、三套皮肤与 Idle/Run/Jump 动画；加载失败时保留程序化角色作为降级方案。
- [x] 重置与可观测性：刷新还原初始世界；R 提供角色安全点/车辆泊车恢复；Canvas dataset 与 `render_game_to_text` 暴露控制模式、居民、车辆和镜头状态。
- [x] NPC 与车流扩容：12 名居民分布在广场、住宅街、港口和温室区域；5 辆车辆中 3 辆持续沿道路巡行，当前可玩区域保持可见活动。
- [x] 交通 AI：车辆按道路节点行驶，检测前车后减速；持续拥堵会换向重选路线，弃置车辆离屏 45 秒后按道路节点回到停车点。
- [x] 动作升级：受控角色区分步行、奔跑、普通跳跃和矮障碍翻越；上下车包含靠近车门、车门开合、坐入隐藏、下车落位和动作淡入淡出。
- [x] 防卡死工具：角色和车辆记录最后安全位置，R 原地恢复；NPC 释放后回归路线；跟随镜头具备建筑遮挡回退，`?debug=1` 可视化碰撞盒与人车路线，世界状态可导出。

## v0.4 世界生活层

本阶段在可玩闭环之上补足“即使玩家不操作，世界也在生活”的持续活动。居民、车辆和地标共享同一帧内快照，不把高频状态提升到 React。

- [x] 居民作息：按通勤、工作、休闲和休息四个时间段调整行为；深夜居民返回各自路线起点休息。
- [x] 居民社交：邻近且空闲的居民会成对停步、朝向彼此并挥手问候，短暂显示社交提示后恢复原路线。
- [x] 人群分离：邻近居民获得平滑的横向分离修正，受控角色保持玩家输入优先，降低重叠穿模。
- [x] 行人安全：道路车流、自动泊车与玩家驾驶车辆共同检测前方行人，根据距离降速或停车；车内角色不作为本车障碍。
- [x] 港口活动：港口吊机持续旋转吊臂并升降货箱，保留实体底座碰撞。
- [x] 温室与灯光作息：温室作物随日照改变生长姿态，镇区路灯随夜色和恶劣天气增强亮度。
- [x] 运行时可观测：Canvas dataset 暴露居民动作、日程、社交对象以及吊机、货物、作物和路灯活动值。

### v0.4 验收

- 无玩家操作时，居民问候、道路车流、吊机装卸、温室作物和路灯变化持续可见。
- 居民相遇不会长期叠在一起；问候结束后继续原有工作或路线，深夜进入返程休息。
- 车辆前方出现行人时可观测到减速或停车，不会把车内角色误判为障碍。
- test、typecheck、check、build 通过；1440×900、1024×768 无横向溢出，当前浏览器 Console 无新增错误。

v0.4 世界生活层于 2026-08-11 完成首批实现。飞艇进出港、完整吊运任务链、区域职业调度和更复杂的群体寻路继续保留为后续迭代，不计入本批完成范围。

## v0.5 动作、导航与交通精修

本阶段提升直接游玩时的连续感与道路可信度，保持无生命值、无复杂事故物理和刷新后重置的边界。

- [ ] 角色动作缓冲：已有速度与朝向缓冲首版，仍需按玩家手感复核起停、急转和碰撞后的连续性。
- [ ] 动画衔接：已有 Idle、Walk、Run、Jump 与上下车首版；正在逐项修复步态幅度、脚步相位、重复弹跳和动作链完整度。
- [ ] 人行导航：已有职业路线与斑马线图，仍需消除无目的循环、原地往返和不自然改向。
- [ ] 实际人群分离：已有碰撞分离首版，仍需消除相遇后同步背向、突然弹开和局部僵持。
- [ ] 车辆实体避碰：已有安全圈、状态感知跟车和“短距倒让后安全借道”首版，仍需复核会车、复杂路口、连续停车绕行和玩家车辆混行。
- [ ] 路口与行人安全：已有路口降速首版，仍需补足车道级优先权、让行和并线规则。
- [ ] 自然泊车：已有末段减速与朝向对齐首版，仍需实景复核车位进入轨迹。
- [ ] 运行时可观测：已有 Canvas 状态字段，仍需补足长时间行为轨迹和异常计数证据。

### v0.5 验收

- 接管居民后，短按和切换移动方向可观察到加速、减速和连续转身；停止输入后动作平滑回到待机。
- 无玩家操作时，居民沿人行区域和斑马线持续活动，近距离相遇不会重叠穿模或永久僵持。

## v0.6 微观生活玩法

本阶段把已有居民、道路和职业活动串成可反复观察与介入的轻量玩法，不增加对话树、奖励数值、服务端或刷新后的持久化。

- [x] 随机世界事件：每次刷新从港口卸货、温室补水、包裹投递、路边检修和访客指引中选择 3–5 项，按顺序循环发生。
- [x] 自动事件生命周期：职业居民沿人行导航图前往事件点，自动处理约 18–24 秒；事件完成后短暂停留并切换下一项。
- [x] 轻量 E 互动：玩家接管任意居民并靠近当前事件后按 E 参与，约 2–3 秒完成；离开角色或切换控制会取消参与并恢复 NPC 处理。
- [x] 职业身份与日程：十二名居民按通勤、工作、休闲和休息阶段显示职业任务与目的地，世界事件结束后恢复原日程。
- [x] 事件场景表现：五类事件具有独立程序化道具、地面信标和轻微动态效果，排队事件保留环境道具但不显示活动信标。
- [x] HUD 与可观测性：玩家 HUD 显示当前事件、地点、处理者、E 操作和进度；Canvas dataset 与场景文本暴露事件阶段、参与者、完成数和居民任务。

### v0.6 验收

- 全镇视角下可持续观察职业居民前往事件点并自动工作，跨街区任务不会直线穿过建筑或卡在碰撞体上。
- 接管事件附近居民后出现 E 操作提示；参与期间角色停留并执行工作状态，完成后回到职业日程。
- 参与中释放角色会返回全镇视角，事件参与者被清除，原职业居民继续处理当前事件。
- 自动测试覆盖事件选择、生命周期、E 参与、职业日程、释放恢复和跨街区导航；当前 Chrome 完成 NPC 自动处理、接管、E 参与、释放、刷新重置及 1024×768 HUD 验收。

v0.6 微观生活玩法于 2026-08-11 完成首批实现。复杂对话、奖励经济、事件分支、室内任务和持久化仍不属于当前范围。

## v0.7 城镇事件链与车辆任务

本阶段把单点世界事件升级为可连续观察、可由玩家中途介入的城镇协作链。事件仍按刷新随机生成并在本局循环，不增加奖励经济、失败惩罚、服务端或持久化。

- [x] 多阶段事件链：港口补给、温室灌溉、北街加急件、港口支路救援和访客入镇均包含 3–4 个连续步骤；完成当前步骤后保留结果，再由下一名居民或车辆接力。
- [x] 居民与车辆调度：居民步骤沿人行导航图前往任务点；车辆步骤沿道路图自动执行运货、送水、配送、拖车和接送任务，结束后恢复原交通或停车身份。
- [x] 双模式 E 参与：玩家可接管任意居民完成居民步骤，也可驾驶任意车辆抵达车辆步骤目标后按 E 交付；切换或释放控制会取消参与并恢复自动处理。
- [x] 专属任务动作：搬运、递交、接收、检修、浇水和指引使用不同的身体姿态、手持道具与节奏；外部骨骼角色保留动作混合并叠加轻量身体反馈。
- [x] 场景结果反馈：每个步骤拥有独立道具、信标、动态部件和完成标记；已完成步骤保留结果状态，当前信标推进到下一地点。
- [x] HUD 与可观测性：玩家 HUD 显示事件链名称、步骤序号、当前处理者、目标位置、E 操作和进度；Canvas dataset 与场景文本暴露阶段、参与类型、动作和车辆任务状态。

### v0.7 验收

## v0.12 驾驶员与可扩展居民路线

本阶段修正“空车自行行驶”和“地图扩大后居民仍困在旧路线”两类违和感。车辆移动与居民路线继续由同一帧循环驱动，不增加服务端、持久化或完整导航网格依赖。

- [x] 移动车辆必有驾驶员：固定车流显示常驻通勤司机，玩家驾驶显示当前居民，事件车辆显示服务司机，自动泊车显示代驾。
- [x] 空车状态约束：真正停稳的空车隐藏驾驶员；正常下车后车辆停在原位，释放控制或任务结束触发自动泊车时先显示代驾，停入车位后再离开。
- [x] 车内驾驶细节：驾驶员包含头部、头发、上身、握方向盘手臂与方向盘，在透明车厢内保持坐姿；驾驶员身份写入车辆快照和 Canvas dataset。
- [x] 职业主路线：维修工与港口工人守港区，园丁与花艺师往返花园和东区，学生、面包师与咖啡师保留生活半径，减少无目的跨城往返。
- [x] 流动职业覆盖：旅人、快递员、摄影师和巡逻员读取导航图中的 `district-anchor`，按稳定分组分担街区覆盖，并按相邻距离重排各自停靠顺序。
- [x] 扩区契约：后续新增街区只需把一个已连通的人行节点标记为 `district-anchor`，新街区会被自动分配给至少一名流动职业，不再让所有居民重复跑遍全图。

动作与日程精修已补充三个可验证约束：中远景可见角色按降频帧累计完整骨骼时间，不再把 2/4 帧降频误做成慢动作；Walk/Run 的髋部垂直控制振幅已单独压缩，避免与角色根节点形成重复颠簸；固定职业通勤和休闲途中不再在错误中间点长时间停留，流动职业的工作巡线仍保留沿途任务停靠。车辆自动转向降低峰值角速度，泊车末段使用单一转向器并在车位内停车对齐，借道安全圈扩大到 2.68 米。以上仍属于精修过程，尚不能替代真实键盘长时间奔跑、复杂路口交通和近景模型观感的最终验收。

固定主角进一步增加了随速度变化的前倾、转弯侧倾和停步回正惯性，外部骨骼模型与远景程序化模型共用同一姿态信号；松开奔跑键后会等实际速度降低再切换 Walk，跳跃动画改为单次播放并在落地后按当前速度回到 Run/Walk。玩家从副驾侧上车时会绕过车头或车尾到左侧驾驶门，不再用直线轨迹横穿车身，车门也改为接近后再开启。Chrome 连续 25 秒采样中移动车辆均有驾驶员，居民最小中心距约 0.75 米，车辆最小中心距在页面两位小数精度下约 2.66 米。自动化尚不能稳定保持 WASD/F 真实长按，因此主观操作手感、完整上下车表演与 10–30 分钟体验仍保持待验收。

NPC 临时让行、接近和跟随玩家后，现在会投影到最近人行路段中的连续点并平滑接回，不再使用反应前的旧路段进度瞬间跳回；测试复现的单帧 1.96 米跳转已降到 0.35 米以内，临时移动也会继续推进脚步相位。居民拥挤避让增加选边滞回和单帧偏移限速，修复避让从道路一侧直接翻到另一侧造成的横跳；18 名居民 60 秒确定性测试覆盖了单帧位移、连续急转和窄路间距。居民任务车和自动泊车的道路阶段改为使用右侧车道目标，不再长时间沿中心线跨区行驶；无信号交叉路口按已进入路口、玩家车辆、预计到达顺序决定单车通行，等待车辆在路口外停车。车辆重叠兜底以沿车身前后退让为主，并限制每帧横向修正，避免接近前车时突然侧移；车头角度每帧归一化，长时间循环不再累积到数十或上百弧度。居民上车隐藏后会进入明确的 `driving` 状态，停止旧人行路线和隐形骨骼更新，由车辆保留同一驾驶员身份。跟随镜头会临时裁剪挡在相机与主角之间的非玩家居民，NPC 模拟和碰撞仍然保留，Chrome 复验已消除前景头部遮满屏幕的问题。Chrome 40 秒采样已覆盖邮差步行取车、上车、驾驶、泊车、下车和末段步行，移动车辆均有驾驶员且未采样到短时反向掉头。更高密度动态交通、10–30 分钟体验和玩家实际驾驶手感仍未完成验收。

后续动作与交通精修让待机恢复 Walk/Run 时继承每名居民自己的脚步相位，避免多人同步迈步；无停留路线节点会使用 0.6–1.05 米前瞻提前转身，有工作停留的节点仍先到位再转向。车辆路口目标改为进入与离开右侧车道的几何交汇点，已越过停止线的车辆保持清空路口优先权，借道检测也不再忽略已停车的对向车辆。车辆接近小路点但车身尚未对齐时会先降速转正，取消把实际位移强行吸向目标造成的横移或反向弹回。六辆固定交通车三分钟确定性压力测试中，每辆累计行驶约 613–682 米，未出现车身重叠、长时间死锁或方向反弹。真实玩家视角的连续转弯观感和 10–30 分钟主观驾驶仍保持待验收。

近景动作继续收敛跑步颠簸和僵硬转向：外部骨骼的步行/跑步垂直起伏分别压到资源幅度的 12%/18%，当前加载资源的实际循环范围为 0.0044/0.0076 世界单位；视觉朝向改为带角加速度的起停和制动，逻辑朝向在无碰撞时跟随真实位移、受阻时保持玩家输入，模型惯性不再反向驱动跟随镜头。Chrome 按 Canvas 的 500ms 状态刷新节奏连续复核 10 秒，21 次刷新中视觉角速度峰值 4.126rad/s、角加速度峰值约 7.95rad/s²，未出现超限跳变。浏览器自动化仍不能可靠保持真实 WASD 长按，因此主角急转、跑停和贴墙的主观手感继续保留为人工键盘验收项，不把本次数值验证扩写为整体动作体验完成。

居民日程与人群移动已增加可重现的早晚高峰约束：早间通勤和晚间休闲均从当前位置按人行图最短路径直达职业地点，到站居民使用路侧驻足槽而不占据导航节点中心；直达路线进度按碰撞后真实前向位移推进，受阻时不再“逻辑到站、模型留在原地”。行进者会提前绕过静止居民，首选侧被建筑挤压时切换可通行侧，取得横向净空后恢复前进；基础巡游则保持当前通行侧，并统一限制单帧人群偏移。确定性模拟已覆盖 17 名自主居民全员到达、最小人际距离大于 0.75 米、60 秒巡游单帧位移小于 0.35 米且可见反打不超过 2 次；上下车落脚点与行人重叠时保留立即清空例外。这些约束不代表 NPC 已达到 GTA 级整体表现；丰富动作、更长时间主观观察和车辆交通继续保持待验收。

冷启动实景复核进一步暴露并修复了“路线进度吸回道路中心”的跳位：障碍侧移后的真实位置现在只按本帧速度追赶路线规划点，矩形碰撞推出和人群安全圈脱离也分别限制单帧修正，不再把几厘米移动放大成数米跳转；60Hz 晚间山地路线回归要求所有居民单帧位移小于 0.12 米，初始化重叠仍在首帧完成安全分离。车辆借道的对向检测从固定 13 米扩展为随对向车速度增长的相遇窗口，六车三分钟压力测试同时约束单帧总位移与横向修正。修复后的 Chrome 冷启动复测被浏览器安全策略自动拒绝，因此本段只记录代码与确定性测试结论，真实页面长时间观察仍保持待验收。
