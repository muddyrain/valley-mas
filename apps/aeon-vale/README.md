# 纪元谷 · Aeon Vale

以 WorldBox 为体验参照的 Godot 造世游戏。中文名由用户指定，英文名为 Aeon Vale，项目放置于 `apps/aeon-vale`。

当前源码版本：0.14「沧海桑田」。平原和森林土壤先是裸土，播种后才具有生态；地表改为稳定、低对比的像素纹理。玩家地震真实升降土地并损伤植被，近景完全隐藏云体与云影；默认窗口扩大，主菜单留白与按钮对齐。保留既有雨、酸雨、龙卷风、植物生命与森系界面；存档升级 v11，兼容 v1–10，生物和文明仍待后续阶段。范围见[产品计划](./docs/PLAN.md#第十四轮土壤地震与窗口修订)，构建及原生证据见[验证记录](./docs/VALIDATION.md)。

## 运行

Windows 0.14：[启动纪元谷](./build/AeonVale-0.14.exe)，与旧版共用玩家存档目录。独立版本文件保留旧版；先在旧版保存世界，再打开新版。构建产物不进入 Git，换电脑或重新检出时可按根项目指南导出。[土壤与地震录像](./test-output/AeonVale-0.14-soil-earthquake.mp4)展示铺土、播种、地形升降和近景降雨。

源码入口为 `project.godot`，可用 Godot 4.7.2 打开。`run.ps1` 自动查找 PATH 或 Downloads 中的便携式 Godot，也接受 `-GodotPath` 或环境变量 `GODOT_BIN`。启动、编辑、测试、运行时截图与导出命令集中记录在[项目指南](../../docs/PROJECT_GUIDE.md#aeon-vale原生-godot)。

## 当前内容

- 启动资源准备、原创开场插画、主菜单、实际地图生成进度及过渡动画。默认窗口最大 1600×1000，并按显示器可用区域缩小；标题卡居中留白，上下按钮行对齐。
- 象牙白、鼠尾草绿与森林色文字的统一界面；原创山谷插画、可缩放工具图标及叶片边饰覆盖标题、加载、建图、存读档、设置及浮层。控件使用轻描边和清楚的选择态，移除重复阴影与按钮星芒。
- 主工具栏集中世界管理、观察入口和世界信息；图标页签进入世界塑造、自然及灾难、动物/生物/怪物，悬停显示描述；返回主工具栏保留当前神力。未开放的气温和生物按钮有不同样式，不能施法。地图顶部无状态栏。
- 八种世界模板、三种地图规模、世界名称、植被丰度和河流开关。模板缩略图随游戏附带，选择及调参不生成世界；右侧可切换至地形细调页，调整陆块大小、额外岛屿和海岸曲折，返回后保留参数。点击创建时才随机生成并显示实际加载进度，示意图不代表最终海岸轮廓。
- 开局以草原、温带森林和桦木林为主，其他自然区域按环境出现，幻想生态为少量点缀。沿连续岸线生成沙滩、浅滩、近海和深海；河道连接水体，林冠与地表在远景保留主要层次。
- 九种可塑造的土地/水体形态，另兼容旧档地裂；18 类独立生态包括草原、温带森林、桦木林、针叶林、热带草原、热带雨林、金色秋林、雪地、干旱荒原、湿地、樱花林、竹林、花海、蘑菇林、晨光果林、水晶原野、翡翠林和糖霜林。
- 68 种植物（37 种林木与幻想树种，另有仙人掌等植物）及两类岩石，每种植物有三种实际轮廓变化，经历萌发、幼苗、生长、成熟、衰老与死亡，自然补充并限制密度。
- 1x 下每年 84 秒；树木 3–5 年成熟，草花半年至一年，灌木 1–2 年；林木总寿命 35–80 年。枯木约半至四分之三年分批消解，原区域通常在半到一年内出现新苗，再按原有速度长大；健康适生旧树保留，自然树苗可让低矮草花让位。不适生草本灌木消失，变为水体时清除植物，变化伴随短动画。
- 世界塑造分海洋河流与土地山川；自然及灾难按气温、灾难、生态种子、滋养分组，其左侧为返回及常驻暂停/沙漏。
- 铺平原/森林土壤得到暖色裸土，不能直接施肥造出未播种的生态；生态种子建立或改变平原土壤、森林土壤或丘陵上的生态，保留底土地形，等待草木自行长出或继续施肥；不适生旧植物立即转枯或消失。水体、沙滩和裸岩山峰先用地形工具改造。取消逐棵树种播种入口，浆果丛神力直接放置可见灌木。
- 18 类生态受当地冷暖、湿度和地势约束，在相邻适生土地上缓慢竞争，也可逐步侵入裸土，玩家播种的生态同样参与；水体、沙滩、山峰与裂隙阻隔扩散。约 1–3 年可见边界变化，长时间逐步改变区域轮廓。设置中的“生态扩散”随世界保存，新世界开启，旧存档默认关闭；关闭不影响植物生命过程。
- 植物肥料在适生空位催生当前生态的草花灌木，树木肥料催生对应树木或巨菇，两者也催熟已有的对应幼苗。两类肥料先清理作用区内枯木与不适生旧植物，保留健康适生的树木、灌木和岩石；树肥可替换低矮草花。主动结果立即写入世界，用约 1.25 秒的出现动画表达；暂停时也完成，倍速不改变反馈时长，不加速成年后衰老。按实际间距控制疏密，正常已满不会冒叉；水体、裸岩、岩石占位等真正无效位置才少量提示。旧存档尚未结束的肥效继续保留。
- 闪电以白色分叉光柱击中落点并可能点燃植物，空地或水上也有短反馈；火焰用像素帧表达蔓延烧毁。雨以蓝色雨滴和水花扑灭火焰，不加速植物生长。新增酸雨神力：绿色雨滴令落点和残留云经过的树木转枯、草花灌木退去，保持原土壤与生态，不自动生成破坏性酸雨。
- 玩家地震沿不同走向的分支断层升起或降低真实地形，可形成丘陵、山地、沙岸或水道；同一区域的生态覆盖被剥离，失去水下支撑的植物清除，受损陆地保留枯树。沿断层扬尘、地图短暂震动后回位。地形、覆土与高度共同保存和撤销；裸土重新播种或由相邻生态缓慢侵入。旧地裂与旧痕迹可继续加载。
- 龙卷风存续 24 世界秒，从小变大再缩小消散，漏斗旋转摆动、路径弯曲、阴影随大小变化，实际破坏半径与显示大小同步。持续火焰、龙卷风及雨/酸云遵守暂停、倍速并保存，短施法动画在暂停时仍可观看。海面有少量缓慢起落的白色波纹，遵守世界时间，不造成洪水或改变地形。
- 自然天气默认开启，每隔 1–3 世界年偶有局部雨云经过，持续 10–20 世界秒。设置可关闭自动降雨，手动雨神力仍可使用。雨神力立即灭火，暂停时播放短反馈；残留雨云等待世界继续后移动和持续灭火。云影与雨丝只覆盖局部，不额外催熟植物。
- 少量晴天浮云缓慢经过，使用分层像素轮廓和独立云影，近景前逐渐淡出、近景完全隐藏云体与云影；不降雨、灭火或催熟。最多四片，暂停和倍速作用于移动与寿命；自然天气关闭后停止自动生成，已有浮云与雨云按剩余寿命结束。晴云、雨云和酸雨云均随世界保存；近景隐藏云体与云影，雨滴仍可见。
- 同一世界连续缩放，最大放大倍率为 32，提供俯瞰、中景、近景入口；远景用稳定林冠概括植被，中近景展开清晰树形。镜头复用已提交的植物绘制，变化区域分帧更新，地表按块上传。自然萌发和长大动画只在近景播放；植物本身继续生长，主动施法在远处使用简化反馈。
- 原创像素地表：深浅海水、湿沙与干沙、暖色裸土、低对比草地颗粒、小幅阶梯色调、丘陵坡面、岩层与积雪山脊。细纹服从区域底色，不随时间随机闪变；新绘法直接用于旧地图。
- 每次真正创建都取得新的随机种子，生成种子在内部保留用于存档，不在选择地图时显示。
- 左侧神力卡上方是独立笔刷按钮，神力图标与 × 共用同一张卡片；× 取消神力。沙漏采用同样结构临时替换，先只显示当前倍率，点击后展开 1x–5x；选倍率或关闭后恢复神力与笔刷。各入口采用统一宽度。
- 圆形、方形、菱形、喷洒四组共 25 档图案；笔刷按钮打开选择窗，Alt＋滚轮调整大小。地图显示无边框浅灰白半透明范围与跟随图标，无效地块压暗；预览与实际笔刷共用范围和适生判断，喷洒落点离散。
- 浏览分类或调整时间保留原神力。沙漏打开时暂停施法，地图仍可缩放和拖动；真正的模态窗口拦截地图操作。观察入口提供俯瞰、中景、近景与植物显隐；撤销/重做按钮及快捷键已取消。
- 暂停及沙漏直接选择 1/2/3/4/5 倍时间速度、三个本地存档位置、覆盖前确认和损坏存档保护。
- 实际可用的全屏设置、90% / 100% / 115% 界面大小与操作手记；界面大小及植物显隐等偏好保存到本地，界面缩放保持当前观察位置。

## 操作

左键使用所选工具，右键或中键拖动地图，WASD 移动镜头，滚轮缩放，Alt＋滚轮调整笔刷大小；没有当前神力时左键也可平移。输入文字、弹窗及加载时 WASD 不移动镜头。闪电、龙卷风和地震每次按下施放一次，其他笔刷可原地长按持续撒落或连续拖动；按住施法不再停止世界时间。空格暂停，Ctrl+S 保存，F 俯瞰。Esc 优先关闭弹窗或时间/观察浮层；地图内有神力则取消，无神力则直接打开设置。在设置中再按 Esc 返回地图。设置中的“操作手记”可查看快捷键。

存档位于 Godot 的 `user://worlds`，Windows 通常对应 `%APPDATA%/Godot/app_userdata/纪元谷 · Aeon Vale/worlds`。删除工程缓存不会删除玩家存档。暂停和倍速作用于植物生态与世界时钟，镜头外的植物同样生长。植物按固定的八组处理点分散推进，不再每秒集中处理整张地图；每个个体的更新频率和生命总速度保持一致。

界面偏好位于同一用户目录的 `interface.cfg`，独立于世界存档。运行检查使用单独的 `user://test-runs/` 目录，不写入玩家的存档和设置。

存档版本为 11，新增裸土状态，继续保存雨/酸云、晴云、龙卷风、环境、边界休整和植物生命。兼容 v1–v10，原地图不重生成，旧档陆地的既有生态保持已播种状态；旧地震痕迹与地裂保留。v4–v7 的年份和植物进度按 84/60 转换，旧枯木保留消解进度比例，活动天气和灾难保留剩余世界秒数。没有对应天气记录的旧档从无活动云开始。读取不改原文件，首次覆盖保留对应 `.v1.bak` 至 `.v10.bak`。新旧时钟、分步更新与边界规则详见 [ADR 0006](./docs/adr/0006-calendar-cohorts-and-stable-boundaries.md)，本轮迁移与检查见[验证记录](./docs/VALIDATION.md)。
