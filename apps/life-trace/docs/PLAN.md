# Life Trace 产品范围与计划

最近整理：2026-09-08

本文件是 Life Trace 唯一的长期产品计划入口，维护当前范围、待办和业务边界。已完成的执行步骤不再堆叠为待办；被取消的方向以本轮收敛决定为准，历史过程可在 Git 中查阅。

## 产品定位

Life Trace 是个人生活助手，围绕计划、生活记录和家庭物品管理提供 AI 辅助。

- 生活安排：创建计划 → 提醒 → 完成计划 → 沉淀踪迹 → 每周回顾。
- 家庭库存：手动 / 拍照入库 → 到期提醒 → 使用或丢弃 → 按需补货。
- 衣橱穿搭：记录衣物 → 获取穿搭建议 → 保存穿搭 → 记录已穿。

底部维持今日、计划、AI、踪迹、我的五个 Tab，库存、采购清单、衣橱等通过二级页面进入。

## 本轮移除决定

以下方向已取消，不再作为隐藏模块或后续能力池保留：

- 灵感 Inbox：页面、文本 / 链接 / 单图采集、AI 整理，以及转计划、踪迹、账目、地点和书影音的全部转换链路。
- 智能菜谱：生成、历史、详情、加入计划、视频占位链路和两枚专属成就。
- 轻账本与订阅续费：页面、统计、AI 记账、快捷记账、采购 / 库存联动和续费推送。
- 地点库：自动归集、常用地点选择、手动管理、收藏、导出及关联 ID。
- 书影音日记：管理、AI 补全、关联 ID 和自动同步链路。

页面路由、API 客户端、状态、类型、服务端路由与处理器、AI 工具 / 提示词、模型注册及专属测试一起移除。旧前端地址统一由现有兜底路由回到今日，服务端下线端点返回 404。

### 数据库迁移与历史记录

新增 PostgreSQL / MySQL 同版本迁移 `202609080001_retire_life_trace_modules.sql`，位于 `server/internal/dbmigration/` 对应方言目录。

- 删除专属表：`life_trace_places`、`life_trace_inbox_items`、`life_trace_media_diary_entries`、`life_trace_ledger_entries`、`life_trace_recurring_payments`、`life_trace_recurring_payment_deliveries`。
- 删除计划 / 踪迹的 `place_id`、踪迹的 `media_diary_id`，以及偏好中的三个 `subscription_reminder_*` 字段。
- 保留计划、踪迹、库存、采购、衣橱和家庭数据。由旧模块生成的计划 / 踪迹保留，地点文本保留；旧记录不再依赖被删除的模块。
- 同步移除 GORM model registry、AutoMigrate 和 schema sync aliases，避免部署后重建下线结构。已发布的历史迁移保持原样。
- 本轮不连接真实数据库执行迁移；发布时走仓库既有迁移流程。迁移会永久删除上述模块的数据，发布前应备份；代码回滚不能恢复已删数据。

## 保留模块的业务边界

### 计划与踪迹

- 计划完成生成踪迹；周期计划完成后派生下一次，历史计划不被覆盖。
- 地点是可选文本，不再自动写入地点库，不再关联地点或书影音 ID。
- 踪迹允许显示历史来源标签，不恢复对应模块的入口或写入链路。
- 核心数据同步到 Go API，localStorage 只作为非核心状态和短期缓存。

### Pantry 与采购

- 库存属于 household，存放位置仍是库存业务字段，不受地点库移除影响。
- 部分使用 / 丢弃和全部用完 / 丢弃保持现有确认流程；采购勾选只更新已买状态。
- “仍在使用”物品退出到期风险桶并停发过期提醒，但仍计入在库总量，可恢复提醒。
- 列表状态、分类、排序和包含已过期开关按云端偏好恢复，显式 URL 参数优先。
- 商品识别只产生可编辑草稿，确认后入库；保质期线索不足时不编造日期。

### 家庭空间

- `Household` 是统一空间抽象：`personal` 和 `shared`。
- 每个用户始终拥有一个个人空间，个人空间不可解散。
- 用户加入共享家庭后，个人空间仍然存在。
- 库存永远属于某个 household，不直接属于某个 user。
- 用户加入家庭时，不自动迁移个人库存。
- 家庭解散后，家庭库存保留在原 household 上，进入只读归档态。
- 普通成员可以退出家庭。
- owner 如果要退出且仍有其他成员，需要先转移 owner。
- owner 是最后一位成员时，应走解散家庭流程。

已落地能力：

- 通用 household model。
- personal household 自动创建和回填支持。
- household API：列表、详情、创建、成员、邀请、加入、退出、转移 owner、解散。
- Pantry 按 household 查询和权限校验。
- Pantry 家庭空间切换和家庭管理入口。
- 邀请码复制、重新生成、撤销。
- 共享家庭详情、成员列表和归档家庭只读展示。
- 个人库存移动或复制到共享家庭库存，支持重复预览、合并数量或保留两条。

### 衣橱与穿搭

- 个人衣橱仅本人可见；共享家庭只展示主动共享的衣物和穿搭。
- 共享穿搭只能引用共享衣物，不能暴露未共享的个人衣物。
- 拍照识别后确认字段和所属空间再入库；标记已穿形成穿搭来源踪迹。

### AI 与图片

- 模型调用由服务端统一代理，前端不保存密钥、不直连模型。
- 对话仅开放现有计划与库存动作；图片和建议草稿由用户确认后保存。
- AI 不可用不阻断手动流程。真实模型质量需要单独验收。
- 药品、保健品、婴幼儿食品只做库存信息整理，不输出医疗或安全结论。

### 商品拍照分析

接口：

```text
POST /api/v1/life-trace/ai/pantry-photo-analysis
```

请求只走 AI 商品识别，不再提供独立文字识别拍照模式；AI 返回商品草稿时可包含生产日期、到期日、保质期天数和日期线索。只有识别到到期日，或同时识别到生产日期和保质期时才自动回填到期相关字段；仅识别到“保质期 9 个月”这类无日期锚点线索时只提示用户确认，不写入表单日期字段；没有日期线索时仍可作为普通商品拍照录入。

AI 返回草稿字段：

- `name`：商品名称。
- `category`：分类，例如 食材、饮料、零食、药品、日用品、护肤、清洁、其他。
- `brand`：品牌，可为空。
- `spec`：规格，例如 `500ml`、`2kg`、`12片`。
- `quantity`：数量，默认 `1`。
- `unit`：单位，例如 件、瓶、盒、袋、个、包。
- `storageLocation`：建议存放位置。
- `expiresAt`：保质期日期，可为空。
- `purchaseDate`：购买日期，默认今天或空。
- `tags`：标签。
- `confidence`：整体识别置信度。
- `warnings`：识别不确定、保质期不可见、需要用户确认等提示。
- `cropBox`：建议裁剪框，保留服务端响应兼容。
- `source` / `model` / `modelTag`：本次识别使用的 AI provider、模型名和展示标签，例如 `Gemini · gemini-2.5-flash` 或 `ARK · ep-...`。

用户可编辑字段：

- 商品名称。
- 分类。
- 数量和单位。
- 购买日期。
- 保质期。
- 存放位置。
- 所属家庭空间。
- 默认提醒规则。
- 备注。
- AI 缩略图。
- 商品标签：主分类保持食品、日用品、药品、宠物、其他等稳定大类；标签用于记录冷冻、零食、调料等可自定义细分类。

### 透明封面策略

- 入库时保存原图 URL 到真实图片字段。
- AI 缩略图字段默认留空。
- 列表卡片优先展示真实图片。
- 透明封面只在用户手动点击“生成透明封面”时触发。
- 主路走服务端 remove.bg，API key 只放在服务端环境变量 `REMOVE_BG_API_KEY` 中。
- remove.bg 配置缺失、额度耗尽或请求失败时，自动使用浏览器本地 IMG.LY 模型兜底。
- 透明封面结果作为 `thumbnailUrl` 候选，不覆盖真实图片。
- 如果未来希望完全离线且不依赖 IMG.LY 默认模型 CDN，再单独评估自托管模型文件、`rembg` / RMBG sidecar 或其他 provider。

## 导航、提醒与 PWA

- 主 Tab 根页显示底部导航；详情和其他二级页面隐藏底部导航，使用顶部返回栏。
- 优先适配 390px 移动端，禁止页面横向滚动；沿用主题 token、安全区和已有布局组件。
- 计划可导出 `.ics` 日历事件；系统通知、计划 / Pantry 提醒和每日简报继续保留。
- Web Push 采用外部 Cron 扫描；Vercel Serverless 配置 `WEB_PUSH_WORKER_ENABLED=false`。设备推送订阅与已移除的付费订阅模块是不同数据。
- 保留 manifest、Service Worker、SPA rewrite、安装 / 更新 / 分享入口和版本标识。
- `/api/v1/life-trace/checkins` 仍是早期 PWA 缓存的空列表 / no-op 兼容层，不恢复每日打卡功能。
