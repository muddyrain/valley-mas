# Eon Vale 产品与交付状态

更新时间：2026-08-12。

## 产品定位

Eon Vale（纪元谷）是一个浏览器单机 2D 像素神明沙盒。核心体验不是随机移动单位演示，而是可持续演化、可被玩家干预且可存取的活世界：居民出生、成长、工作、建设、获得装备与身份；聚落发展经济并建立王国；王国可能结盟、开战或灭亡；动物参与觅食、逃跑、捕食和繁殖；神力会改变真实模拟状态。

## 已交付状态

- **阶段 0 性能骨架**：Web Worker 固定 20 Hz 模拟，主线程快照插值，实体状态使用 Packed TypedArray；个体寻路使用带预算 A*，战争群体移动使用 Flow Field，局部避让使用空间哈希。
- **PixiJS 8 真 2D 渲染**：不再使用 Three.js、透视相机或斜视角。地图固定正北，只允许有边界的平移与 `0.5/0.75/1/1.5/2/3/4` 阶梯缩放，缩放锚定指针，不支持旋转和倾斜。
- **三级地图 LOD**：世界层使用每格 1 像素的宏观纹理，只保留连续海岸、大片生物群系、聚落名称和资源叠层；聚落层使用 4 像素区划纹理并显示抽样居民、抽样资源、道路与建筑；居民层显示完整居民、建筑与资源节点。地形 Chunk 原位更新，地图只同步脏单元，资源只同步脏节点，不在周期快照中传输或重建整张地图，避免整屏闪烁。
- **有限世界**：支持 128、256、384 三种地图，默认 256；支持确定性群岛、主大陆和空白海洋，边界始终为深海，同一种子可重放。空白海洋不预置居民或动物，需玩家先创造陆地和生命。
- **地图编辑**：升高、降低、陆地、水域、森林、食物、石料与清理；森林、石料和清理直接创建或移除独立节点，编辑仅使受影响导航 Chunk 失效，并同步脏单元与脏节点。
- **V4 个体人口系统**：所有居民都是持续存在的真实个体，拥有年龄、性别、家庭、伴侣、父母、健康、饥饿、精力、职业、等级、经验、贡献、身份、装备、特质、携带资源、资源目标和个人经历。初始人口采用平衡年龄结构；出生来自同村伴侣并继承家庭关系；居民会老去，并按寿终、饥荒、疾病、袭击或灾害记录死亡原因。
- **动态承载力与迁徙**：村庄承载力由住房、农田产能、储粮趋势和安全共同决定。人口压力按“抑制出生 → 消耗储备 → 先遣家庭迁徙 → 长期饥荒”分阶段响应；适龄伴侣可组成共享 Flow Field 的先遣队，真实移动并建立新聚落，而不是瞬移或生成替身。
- **像素居民与王国识别**：居民由肤色、头发、衣服、王国色、职业工具、身份和装备分层生成；无王国居民使用中性色。建筑、居民和旗帜共享王国色，同一套像素实体在世界、聚落和居民层连续缩放，不替换为战略圆点。
- **动物生态**：鸡、羊、牛、鹿、狼、熊六种独立侧面像素轮廓。食草动物觅食并躲避捕食者；狼和熊优先捕猎野生动物，只有极度饥饿且远离聚落时才会攻击居民；各物种在容量约束下繁殖。
- **独立资源节点**：树木、露天石料和金属矿脉使用可扩容 TypedArray 存储和 `8×8` 分块索引，384 地图稳定生成约 2.95 万个节点。树木按树桩、幼苗、幼树、成熟阶段通过到期事件再生，石料和矿脉保持有限；节点只参与局部软避让，不使全局 A*/Flow Field 失效。512/768 地图已覆盖生成、索引、V4 保存和恢复。
- **需求驱动经济与有机布局**：食物、木材、石料、金属、黄金、工具与装备构成资源闭环；伐木工和矿工只在库存低于人口目标时出工，预留节点后采集并真实携带回仓库，完成入库前不增加村庄库存。金属开采要求先在有限矿脉附近建成矿场，不再由矿场或伐木营地定时凭空产出资源。住房围绕中心生长，农田位于外圈，生产与公共建筑形成小型功能区，道路连续连接中心和建筑。
- **施工物流**：建筑选址会先锁定一次成本，清理范围内的真实资源节点并回收材料，再由搬运者分批送达工地；全部材料到位后建筑工才推进施工阶段。清障、运输、施工、受损和摧毁状态均可被地图反馈观察。
- **王国战争**：村庄形成王国并维护和平、联盟和战争关系。守卫沿共享 Flow Field 集结和进攻，攻击真实损伤聚落与建筑，王国可以灭亡。领土、战争方向、施工、受损、摧毁和攻击命中均有地图反馈。
- **十六种神力**：降雨、雷击、火焰、龙卷风、陨石、瘟疫、祝福、治愈、狂暴、和平/战争、诅咒、生长、冰霜、地震、净化、繁盛；均作用于真实环境、资源节点、实体、建筑或外交状态。生长会创建或催熟树木，火焰会烧毁树木，陨石与地震会移除命中节点。
- **观察与操作**：全屏地图、紧凑顶部状态、底部工具与时间控制、按需展开的世界局势和检查器。顶部人口入口展示趋势，并可展开出生、死亡、迁徙、承载力、年龄结构、住房、储粮和死因诊断。居民检查器包含概况、成长、装备、经历四页，并支持收藏和跟随；聚落名称、悬停高亮和选择轮廓持续跟随目标。
- **V4 存档**：Zod 校验的版本化 JSON，开发期不迁移 V1–V3；V4 持久化独立节点、再生事件、居民携带物、目标节点和施工物流状态，使用独立 IndexedDB 命名空间保存三个手动档和三个滚动自动档，并支持导入导出。单槽写入使用临时记录后替换，失败时保留上一份有效档案。
- **音频**：Web Audio 程序化环境底噪和创建、神力、危险、选择提示音，可静音，不依赖外部素材。

## 阶段 0 浏览器实测

环境：自动化 Google Chrome 151、macOS、1440×900、设备像素比 1。三档均加载 128×128 确定性群岛作为代表性地形，预热后进入 4× 居民近景并读取实时遥测。Draw Calls 是按 PixiJS 可见纹理批次计算的透明估算值，不冒充 GPU 驱动计数。

| 居民数 | FPS | 平均 Tick | P95 帧时间 | 批次估算 Draw Calls | 三角形 | 近景可见居民 | 寻路队列 | Long Tasks |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 119.5 | 0.22 ms | 9.7 ms | 3 | 80 | 37 | 1 | 0 |
| 500 | 119.5 | 0.67 ms | 10.1 ms | 3 | 414 | 197 | 3 | 0 |
| 1,000 | 119.5 | 0.93 ms | 9.9 ms | 3 | 788 | 378 | 113 | 0 |

永久 E2E 门槛为 FPS 大于 20、P95 小于 50 ms、批次估算 Draw Calls 不超过 20、三角形少于 30,000，并要求 100/500/1000 三档近景都发生视口裁剪。当前三档均通过；1,000 居民仍存在 113 个待处理路径请求，但平均 Tick 保持在 1 ms 内。

阶段 1 另有完整世界门禁：384×384 主大陆、1,000 居民、约 29,491 个独立资源节点。Google Chrome 151 近景实测 `118.5 FPS`、`P95 13.6 ms`、`平均 Tick 1.36 ms`、`6` 个批次估算 Draw Calls，满足 `FPS ≥ 60`、`P95 ≤ 25 ms`、`平均 Tick ≤ 4 ms`。

## 架构边界

- `src/simulation` 是无 DOM 的确定性模拟核心；地图和实体使用 TypedArray，村庄、王国、建筑和事件使用结构化对象。
- `src/worker` 负责时间倍率、命令调度、可转移实体快照、地图脏单元、资源脏节点、人口诊断、检查器数据和 V4 序列化；高频模拟状态不进入 React。
- `src/render` 负责 PixiJS 8 WebGL 2D 场景、64×64 渲染 Chunk、三级地形 LOD、像素纹理、插值、分层拾取、覆盖层和即时反馈。
- `src/App.tsx` 只协调低频 UI、设置、选择、IndexedDB 档案和音频。
- 导航与资源索引保持 8×8 Chunk；地形编辑只递增受影响导航 Chunk 版本，使旧路径自动失效。

- Vitest 覆盖确定性随机数、A*、Flow Field、空间哈希、快照插值、阶梯缩放、三级 LOD 决策、连续生物群系、地图编辑、六种动物、家庭人口、动态承载力、迁徙、居民成长与身份、有机聚落规划、资源节点、分块预留、真实携带、施工物流、百年森林、512/768 世界、经济、战争、神力、V4 存档往返、三手动/三自动档轮转和完整世界压力场景。
- Playwright 覆盖新建世界、地图编辑、投放居民、暂停/加速、神力、三级视角、人口诊断、聚落名称、悬停、选择、居民成长/装备/经历/收藏、聚落检查、IndexedDB 保存与刷新载入、100/500/1000 居民代表场景，以及 384 地图、1,000 居民、约 3 万节点的完整世界门禁。

## 剩余风险与下一阶段

1. **长局威胁平衡**：30 年确定性人口与百年森林测试已经稳定，仍需 30–60 分钟 8× 浏览器浸泡，校准极端饥饿捕食、战争、装备产能与王国灭亡速度。
2. **聚落解释性**：在人口面板基础上继续展示各村庄产出、消耗、停工原因、职业缺口、运输瓶颈、矿脉余量和先遣队进度。
3. **王国政治循环**：下一阶段重点是具名领袖、村庄自治与王国统合、低频诉求和受财政/战争/关系约束的叛乱；必须避免高频随机政变。
4. **战斗与救援**：守卫分层响应、倒地救援、专业治疗、个人装备与村庄军械库仍保持冻结，本阶段只保留现有接口边界，不误报为已交付。
5. **正式像素内容与跨设备基线**：当前为程序化像素模型，仍需统一图集、逐帧动画、环境音、素材授权清单，以及低端集显、设备像素比 2、Firefox 与 Safari 实测。

历史回放、多人和后端同步不在当前阶段范围。
