# 最小跨日循环规格

状态：用户已确认 Q6～Q10，本文为 0.2.0 实施基线。跨日规则、装备、界面与保存已落地，交付验证与构建结果见 PLAN.md 和 VALIDATION.md。

0.3.0 继续沿用本文的跨日规则；行动内单搜索上限和旧键鼠方案已由 `adr/0003-parallel-search-and-direct-controls.md` 替代，支持多点并行与直接小队操作。

本文件具体化 [PROJECT_CONTEXT 第 33 节](../PROJECT_CONTEXT.md#33-第二阶段完整-day-loop) 的第一小步；实施进度只记录在 [PLAN.md](PLAN.md)。版本为 0.2.0，以“今天带回的东西改变明天”为验证目标。

## 已确认的设计

- 优先最小跨日循环与可用奖励，保留现有小队指挥和单人任务派遣。
- 战斗阵亡成员在当前 Run 无法恢复；其余成员继续，全部阵亡时本轮失败，新开局仍可使用这些角色。
- 首次缺粮先承受饥饿惩罚，有一个游戏日补粮；连续缺粮才造成人员损失。
- 外出可以找到少量有差异的武器，归航后自由换装；Scrap 可以购买明码标价的备用武器。
- 每次功能交付生成并实际验证独立 Windows EXE。

## 可试玩范围

保留现有三人开局、三个 Trait、四种武器和一张城区测试图；同一 Run 可跨日保留成员、库存、装备与饥饿状态。人数可以因死亡降到两人或一人，不自动补员，本版不增加营救或招募。

以第五个游戏日完成归航和食物结算为本版试玩终点，至少一人存活即可达成；另记录是否三人全部存活。这是小版本的明确结束点，不代替正式版的主线终点，也不代表第二阶段连续 10～20 日的目标已完成。试玩终点可配置，以便后续扩展。

每日地点三选一、完整随机布局、经验与 Trait 成长、定向强化、被动道具、战术能力、Tools、基地房间和长期城市侵蚀在后续小版本进入。

## 归航与食物规则

一次完整结算按照以下顺序发生：记录战斗阵亡与生还成员，归入带回的物资和装备，预览粮食支出与后果，确认口粮分配，处理饥饿或死亡，记录结果，再进入下一天或本轮结束。入账、扣粮、减员与日推进作为同一次结算，不能因重复回调或打开界面而重复发生。

- 只有本轮仍存活的成员需要口粮；战斗中已阵亡者不计入当晚需求。
- 初始数值建议每名成员每日消耗 1 食物、开局库存 6；同时降低普通点的产粮，按补给路线与装备路线一并调试。保守搜寻应提供有限余粮，装备路线可能需要动用储备；当前 13/25 食物的旧路线数值不能直接沿用。
- 足粮时扣除需求，清除连续缺粮记录与饥饿，生还成员休整至正常满血。
- 首次不足时消耗已有口粮，所有生还成员进入可见的饥饿状态；下一天建议按正常生命上限的 80% 出发，以此承担代价，不同时叠加攻击、移动和搜索惩罚。
- 第二个及后续连续缺粮日，口粮缺口对应当晚无法供养的人数。玩家在确认结算前决定优先供养哪些成员；界面直接列出未获得口粮的成员及死亡后果。没有可用口粮时，全部剩余成员可能死亡，本轮结束。
- 饥饿连续天数属于社区，不能通过轮换缺粮成员反复重置宽限。任何一次足粮结算才重置连续记录。饥饿期间的生命上限折减不叠加。
- 营内因缺粮死亡者的装备留在安全屋，解除其装备关系；归航后没有把装备遗留在野外的理由。

这组数值是数据化调试起点，不是已验证的平衡结果；调整必须同时观察可预期的生存压力、补救机会和主动冒险的收益。

## 装备收获与损失规则

- 开局每人实际持有一把基础武器；其他装备要搜到或购买，不再免费列出全部武器供任意取用。
- 区分武器种类与武器个体。两把同型号武器可以同时存在、具有不同属性，并分别交给不同成员；同一把不能同时装备给两人。
- 复用现有四种武器，首批只加入少量直接可读的差异，例如远程武器的射程、弹匣或换弹差异。每个词条限定适用武器，不能给撬棍生成弹匣词条，也不同时引入多层品质和制作材料。
- 进入城区前可知道哪些搜索点可能获得装备；具体武器在搜索完成时揭示。每个点的奖励属于本游戏日，不因重开界面或重试当天而重抽。
- 搜到的武器先属于本次携带收获，成功归航后才能进入安全屋配装；本版不增加战斗中换装。
- 战斗阵亡者当时装备的武器遗失，不自动复制回库存；本版不做拾回遗物的额外交互。生还成员带回队伍已收集的公共物资与未装备武器；全灭时这些携带收获全部遗失。
- 商店提供少量可见的备用武器，每件价格与属性在购买前展示；购买扣 Scrap 并获得一个武器个体。余额不足不扣款、不发货，同一件商品不可重复购买。
- 商店货单按游戏日固定，返回安全屋、换装、重启应用不能刷新。购买和换装立即保存；本版不增加付费重抽、出售或拆解。

## 保存与重开边界

安全屋自动保存当前 Run。出发前保存当日状态和固定的行动奖励；本小版不保存战斗进行到一半的所有角色、敌人和搜索状态。行动中退出或程序中断，续玩回到出发前重试同一天；不会因此重新抽取装备奖励。这一限制在退出提示中明确说明。

归航时先保存待确认的结算结果；若在分配口粮或查看结算时退出，续玩恢复该结果，不能退回出发前刷取同一批收获。确认结算后保存已完成状态。写入失败必须保留上一份有效记录并提供可见提示，不能把半份状态当作成功保存。

重新打开安全屋只重建界面，不重置成员、装备、饥饿、库存或商店。再次出勤只重置当前行动的敌人、搜索点进度和夜间临时威胁。

本轮结束后只能查看结果或重新开局，不能继续派出零人队伍。新 Run 重置本轮日数、库存、装备和伤亡，既有角色定义仍可使用；本版不实现永久解锁或永久属性增长。自动化使用独立测试存档，不能覆盖用户游玩记录。

## 实现边界

- 继续使用 Godot 内置能力与数据驱动的 Resource，不增加第三方依赖。
- 内容定义、Run 状态、单次行动状态和表现各有明确归属。当前按内容目录重建三人的流程改为按本轮生还名单装配，不能只在界面隐藏阵亡者。
- 成员和武器个体使用稳定标识建立装备关系，不继续把数组位置或武器种类 ID 当作个体身份；词条计算不能修改共享的武器模板。
- 粮食规则、商店价格、装备差异、掉落池和试玩结束日来自独立数据。一天只允许一个行动结果完成结算，保存恢复也保留这个状态。
- 保留现有 Debug Menu，并提供日数、饥饿、库存和指定武器差异的调试入口。调试记录与正常自动化断言明确区分。

## 交付验收

1. 连续三人、两人、一人出勤时，成员名单、装备槽、耗粮人数和结算分母一致；阵亡成员不重新出现，零人时本轮失败。
2. 最后一人可以搜索、遇险自卫、召回、完成后恢复可控，并完成 1/1 撤离；最后一人死亡只结算一次。无人掩护是危险取舍，不能成为输入或任务状态卡死。
3. 首次缺粮产生惩罚并留下完整的下一天补救机会；足粮解除，连续缺粮执行预览过的人选和后果。三人只剩两份口粮、零口粮、最后一人的口粮不足均有明确结果。
4. 两把同种不同属性武器可同时拥有并分别装备；换装、阵亡、营内死亡、购买和续玩不复制、错绑或丢失无关武器，模板数据不受污染。
5. 重复结算回调、反复打开安全屋、连续点击出发、退出续玩均不多发奖励、多扣粮、重复购买、重复减员或额外推进日期。
6. 验证出发前、待结算、已结算、购买后和本轮结束的保存恢复；行动中退出按已说明的边界恢复。有效旧记录与玩家存档受到保护。
7. 实际运行不同补给/装备路线，覆盖正常归航、带回新武器后换装、首次缺粮后补救、连续缺粮、战斗减员和全灭。自动化记录至少一轮五日完成，并与人工“愿意再出发”的体验验收分开报告。
8. 原有 Headless 规则/行动/派遣回归与新的跨日规则验证通过，完成原生界面输入、窗口适配和新 UI 的实际渲染检查；Windows EXE 重新导出并在独立目录验证启动，交付可点击的运行文件。

验收结果写回 [VALIDATION.md](VALIDATION.md)，实施状态写回 [PLAN.md](PLAN.md)；当前所有上述验收均未因本规格的撰写而自动通过。
