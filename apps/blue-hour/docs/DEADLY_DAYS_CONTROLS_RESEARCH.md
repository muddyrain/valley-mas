# 原版 Deadly Days：并行搜索与操作核查

核查日期：2026-09-08。对象为 Steam App 740080 的原版 Deadly Days；排除 Roadtrip。下文保留研究时的 0.2.0 源码快照，没有运行原作。用户随后授权实施，0.3.0 已补齐多任务与直接操作，现行规格见 [ADR-0003](adr/0003-parallel-search-and-direct-controls.md)，交付状态见 [PLAN](PLAN.md)。

## 结论

原作支持成员分散执行搜索任务，不应理解为全图同时只能一人搜索。公开证据对多点并行的支持较强；没有找到官方逐项定义全部并发边界的操作手册，所以不把同一建筑能否多人加速、建筑内伤害或中断细则推断成已确认事实。

原作的基本操作以小队集合点为中心，成员可被派离队伍搜索。它与传统 RTS 的逐人选择、编组、自由分队不是同一个操作模型。我们之前确认并实现的“一人搜索、其余掩护”是切片范围的简化，不能作为原作规则引用。

## 研究时的项目差异（0.2.0 历史快照）

| 环节 | 原作资料所支持的操作 | 当前蓝时归航 |
| --- | --- | --- |
| 多处搜寻 | 不同成员可以同时在不同目标工作 | 全图仅一个搜索任务；第二目标被拒绝 |
| 普通移动 | 点击设置队伍集合/防守点 | 点击地面移动掩护成员，搜索者保留任务；大方向接近 |
| 连续走位 | 按住左键，队伍持续跟随鼠标 | 只响应按下瞬间；没有持续跟随 |
| 手动射击 | 按住 Ctrl 停步朝鼠标位置射击 | S 停止、F/点击敌人锁定目标；射程不足会接近，含义不同 |
| 暂停 | Space；Esc 为菜单 | Space 定位队伍；Esc 或按钮暂停 |
| 镜头 | WASD、鼠标拖拽、滚轮 | Alt+WASD、滚轮；左右键都走同一套场景命令 |
| 搜索者选择 | 自动按距离，存在切换/取消机制 | 最近可抵达成员，角色面板显式改派与 R 召回 |
| 搜索表现 | 建筑进入搜索有官方修复记录；建筑、车辆不必表现相同 | 所有目标都在可见入口工作，危险靠近/受击暂停自卫 |
| 战场干预 | 有可主动施放的能力，形成额外决策 | 当前只有移动、任务、停止与集火；能力尚未实现 |

源码定位：`missions/mission.gd` 的 `command_search` 在已有 `search_id` 时直接拒绝第二任务；`guards` 只排除一个 `search_task.worker`。`missions/search_task.gd` 保存单个 `site_id/worker`。`_unhandled_input` 仅处理鼠标按下，左右键共用分支；`_process` 只有 Alt+WASD 镜头移动。`ui/mission_hud.gd` 也围绕单个搜索状态显示与改派。

因此，并行搜索不是只移除一个判断就能完成：任务归属、可用人员、多个进度、目标提示、改派/召回、遇险、阵亡和全队撤离需要一起调整。持续跟随与指向射击也需单独处理输入状态；F 的敌人锁定不能代替朝任意位置射击。

## 对迭代顺序的建议

先补行动内的调度与操作，保留已完成的五日循环作为后果承接。建议下一小版聚焦：

1. 多目标并行：每个目标一名执行者、每人最多一个任务；有可用成员才能新增任务。同一栋楼多人加速和无人员时预排任务暂不加入。
2. 允许玩家在一人搜两人守、两人搜一人守、三人全搜之间取舍。零掩护时明确显示状态，不能以“始终保留一名掩护”暗中限制并行能力。此为本作建议，不声称原作所有人数边界已实机验证。
3. 每个目标可查看执行者和进度、单独改派/取消；补全队召回。普通队伍移动不打断搜索，撤离统一召回全部存活者。无人可派时给出明确反馈，不偷换已有任务。
4. 加入按住左键带队、Ctrl 指向射击、Space 暂停、WASD 镜头；F 的锁定集火可作为补充。建筑/车辆应单击明确派遣，按住拖过多个物体不能意外派出全队；取消与派遣反馈要清楚。具体鼠标拖拽键及冲突需实现规格确定。
5. 重测路线与数值：并行后不能继续用原来的串行搜索耗时验证结果，需检查是否能在白天轻易清图。先调整路线、点位距离、资源与可读危险，不先靠延长等待补偿。

保留“归航必须带齐所有存活者”的本作方向。搜索者是否进入建筑、进入后是否受到攻击，是会显著改变风险的独立设计决定；现有“入口暴露并自卫”不能冒充原作，亦不在本次研究中自动改成室内无敌。

验收应包含：三人同时搜索三个不同目标；取消其中一个而其他进度继续；掩护跟随与指向射击不误取消任务；搜索者阵亡释放该任务；零掩护仍能召回；全队撤离等待所有搜索者；暂停时可观察和下令但不推进时间；完成一个目标只发一次奖励。

## 纠正与未决边界

此前只核实“一人离队搜寻”便采用全局一个任务，漏查了并行调度；项目参考文档原已写出的持续跟随，也没有进入当前输入实现。因此，用户感觉操作不一样有实际依据，不能归因于不熟悉操作。

“多个搜索点同时工作”证据较强；精确的取消进度保留、室内受伤、出入建筑过渡、最新原版的全部鼠标绑定仍需原作实机核对。不能把玩家评论中的 Bug 当成应当复制的设计规则。后续 0.3.0 实施已取代 [ADR-0001](adr/0001-squad-command-and-task-dispatch.md) 的单任务上限；原作证据仍维持上述分级，不因本作实现完成而声称原作全部细则已确认。
