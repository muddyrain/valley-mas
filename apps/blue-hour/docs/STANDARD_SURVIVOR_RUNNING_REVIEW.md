# Standard Survivor Running 原样验收

日期：2026-09-18。前置状态由用户确认：165cm Rest Pose、Idle V1、Walking V1 均 PASS。

**结论：有明确跑步特征，建议「较大重构」，保留现有节奏与交替步态作为基础，不建议直接采用，也没有必要完全重做。** 支撑鞋底持续离地、支撑速度不均、循环未闭合；后摆手臂幅度偏大，左右不完全一致。上半身有转动，不属于全身僵硬的快速走路。本轮只提取、播放、量测，没有修改任何 Running Keyframe。

## 数据保真与测量口径

源为正式模板 [survivor_animation_template.fbx](../assets/characters/survivor_animation_template/source/survivor_animation_template.fbx)，SHA-256：`033932ed14562004a68f8a98f305bf3e1d5fb0c2ecc2fbb036639a6cc88dd4b5`。

Blender 只读选择 `target_character|Running`，不保存修改后的 FBX 或 Blend。检查 Action 的 key 时间、值、插值、手柄签名，前后一致。Godot 直接用 FBXDocument 在 24 FPS 下生成源场景，保留不可变轨道，不运行动作优化、修正或 Retarget；只移除独立副本中另外两段动画的注册。原源 FBX 三段动画不动。

源动画没有循环闭合处理。播放器按原时长回到零点，不 CrossFade，不设 Root / Model / VisualRoot Offset。独立导出使用同一内存场景序列化的 `running_source.scn`；其 Running 87 条轨道的键签名与原样播放一致：`f6aef9d8d5c35fe05ad4e6d78fd059a72bb2ce01a7bc320033a556a61c7edc34`。

Blender 与 Godot 各按 120Hz 采样 81 点，含首尾。源键时刻关节位置最大差 0.00772mm；键间最大差 2.889mm，来自 Blender 与 Godot 四元数插值差异，不能称为全周期逐点零误差。Godot 独立 CPU 蒙皮鞋底高度与 Blender 最大差 0.451mm。以下大部分步态量取 Blender 原始求值，接地最低点另列 Godot 实测；精度不足以判断亚毫米差异，但不影响厘米级问题结论。

Heel / Forefoot 与前两轮定义相同：Rest 最低 6cm 鞋部顶点，沿 Foot→ToeBase 水平轴取后 30% / 前 30%，持续跟踪相同顶点。测量地面是 Y=0（Blender Z=0），没有人为归零偏置。

预测滑步是前掌或后跟选区中心的局部后移坐标减去 `速度 × 时间` 后的峰峰差。角色当前不前进，此值只预测未来恒速位移能抵消多少局部移动；不把原地脚后移本身判作滑步，也不将悬空阶段当作真实地面摩擦接触。

两侧速度拟合和候选速度中位数 5.042m/s 表明，当前原速动作适配约 **4.7～5.0m/s**，可先用 **4.8m/s** 作后续制作参考，尚非 Gameplay 参数。若用 5.0m/s，前掌残余为左 35.80 / 右 62.28mm；不存在一个恒速可同时完全抵消两侧。4.8m/s 对应名义单步 1.60m、同脚步幅 3.20m，这对于 165cm 模板属于较积极的跑速与步长；作为慢速 Jog 会显得跨步过大。

左脚 0.167→0.242 秒，Heel / Forefoot 从 55.5 / 83.2mm 降到 17.4 / 18.0mm；随后 0.300 秒升到 51.7 / 29.0mm，出现后跟先抬、前掌后离的方向。右脚 0.567 秒约 15.2 / 7.1mm，0.625 秒约 61.1 / 33.9mm，也有 Toe Off 方向，但全过程缺少可靠的地面支撑，蹬地与落地重量感偏弱。左右落脚形态不完全一致，左侧先后跟、右侧更偏前掌。

Swing 期间脚尖会自然向下，ToeBase→Toe_End 世界俯仰约左 -85.76～19.29°、右 -84.16～20.97°。鞋底前掌相对后跟最大上翘约左 13.15°、右 4.99°，发生在摆动/落脚准备阶段，未见整段支撑持续翘尖。收腿时近竖直的脚尖朝下幅度较大，但没有突然 Toe 翻转。左右 Toe_End 原始局部旋转几乎恒定，变化小于 0.000034°；已知 Rest 轴不镜像仍在，未发现独立突发异常，也不能据此宣称所有动作下都无风险。

## 是否有「跑」的感觉

**具备跑步轮廓与节奏。** 180 步/分钟、收腿折叠、两段双脚高离地和约 10° 身体前倾共同支持这一判断。动作不是 Walking 的简单倍速播放。

严格 Y=0 接触标准下整段都悬空，不能报告“100% 是正常腾空阶段”。进一步看双脚鞋底同时超过 60mm 的高离地窗，存在两段明显腾空形态：约 **0.050～0.167 秒** 与 **0.350～0.517 秒**，按采样格合计约 42.5% 周期；阈值改为 100mm 时为 15%。这些是几何上的高离地阶段，真实腾空占空比需在以后接地成立后重新测量。

膝弯约 145° 的大值主要来自后方收腿，不能等同于前方高抬膝。最大大腿前摆只有约 49～53°，膝盖未抬至髋高，未呈现典型高抬腿训练姿态；但回收脚较高，左侧鞋底高点约 0.777m、右约 0.667m，左侧收腿更夸张。右侧落脚前膝盖接近伸直（最小约 13.84°），两腿没有反折或零弯曲锁死。矢状面有符号弯曲全程同向、骨段长度保持；原 Walking 分析中依赖髋踝高度差的投影指标在 Running 收腿时接近奇点，本轮不使用它判断膝反折。

Hips 起伏约 6.2cm，不比原 Walking 的约 6.2cm 更大；在该步频下有弹跳节奏，但不属于异常强烈的上下蹦跳。视觉上的漂浮主要来自持续接地间隙。前倾和髋胸反向转动提供前进感，落地压缩与蹬离方向存在，可靠受力阶段不足。

左右上臂反相相关性 -0.987，摆臂与腿的交替协调；半周期对齐后左右上臂矢状角 RMS 差 9.72°，动作明显不是完全镜像。左前摆更大，右臂较收，双臂后摆均接近水平，侧面肘部向后抬得较高，手掌保持较展开的形状。这是机械感/夸张感的主要来源，建议后续调整摆臂幅度、肘部路径和松弛感；本轮未改。

躯干 Hips→Neck 前倾 **7.36～12.66°**，均值 **9.65°**；左右肩连线水平转角 **-14.84～15.55°**，约 30.39° 范围。Spine、Chest 与肩部有明显旋转和节奏，未见整体锁成一块。肩胛局部动作较少、手臂路径重复性较强，仍有程序化观感，但不能简单归类为“上半身僵硬”。

Head 世界位置左右 / 前后 / 上下范围约 **13.11 / 30.97 / 71.41mm**；头部轴前倾 **9.15～14.66°**。头主要跟随身体上下运动，垂直幅度比 Hips 多约 9.67mm，没有明显额外甩头；源 Head 局部旋转相对首帧最大约 17.49°，有补偿而非完全固定。

模型和 Armature 对象全周期矩阵不变，Hips 无连续向前推进：前后范围仅 64.34mm，首尾水平差 5.55mm，拟合前进速度约 -0.008m/s（周期不闭合和振荡造成）。因此是 **In-Place Running，无可用的平移 Root Motion**；Hips 是顶层骨，存在正常局部位移，不把“无 Root Motion”解释成 Hips 静止。

## 建议与完成边界

推荐 **较大重构**，理由是问题已超出单一地面高度或少量接缝键：左右支撑段速度和受力需重建，Loop 需同时处理 Hips / Foot / Knee / Toe，摆臂后摆和左右差异也需要美术调整。可保留 0.666667 秒 / 180 步频、交替关系、躯干前倾与旋转、主要 Swing 收腿方向，不必废弃整段重做。

这只是后续建议，不是已授权的修正。本轮没有 Foot Contact Fix、Rest / Skeleton / Skin Weight 修改、Retarget、Combat Jog、持枪跑动或正式角色/Gameplay 接入，也没有新增正式 `running.tres`。

验证结果：

- 独立 Godot Headless Import / Scene Load / 原生捕获 / Windows release 构建与实际启动通过；输出日志无资源缺失、UID 或解析错误，独立程序退出码 0。
- 测量工具的骨骼、绑定、Rest、对象变换和数值有效性 **223 项通过**；它验证验收工具有效，不表示 Running 接地质量通过。
- 正式夏知遥、苏晚星基础回归 **303 项通过**。
- **329 个受保护文件哈希未变**，包含静态模板、已通过 Idle / Walking、正式角色、公共动画、武器与 Gameplay；源 FBX 与独立副本逐字节相同。
- Blender Action 与 Godot Animation 键签名保持；导出程序中键签名也相同。
- 四视频通过 H.264、帧率、帧数、时长、画面内容与运动检查。
