## Runtime path

The formal path is now:

```text
core/main.gd::_mission_config()
  -> core/main.gd::_load_selected_mission()
  -> missions/mission.gd::setup()
  -> maps/expedition/expedition_map_provider.gd
  -> maps/expedition/town_runtime_adapter.gd
```

`_mission_config()` now hands off a deterministic `map_seed` derived from campaign seed, day and mission counter. `--map-seed=<int>` is accepted for deterministic reproduction. The default formal provider is `MEDIUM_TOWN_V1`.

`ExpeditionMapProvider` exposes two explicit modes:

- `MEDIUM_TOWN_V1`: creates the formal `MediumTownRuntime` adapter and loads the existing Town generator plus M00–M03 views.
- `FIXED_LEGACY`: preserves the previous `City` and fixed `east_quay` map path as fallback.

`TownRuntimeAdapter` extends the existing `City` contract so existing Expedition HUD, markers and camera consumers can attach to a real runtime node. It exposes Town bounds, arrival point / forward / exit, mission POI, extraction point, building entries, search points, road bounds, environment root, runtime root and M03 statistics. It does not invent future gameplay data: vehicle search points and enemy spawn zones are `NOT_AVAILABLE_YET`, and `path()` returns empty until E01 owns navigation.

Survivors spawn from the generated bus exit using arrival forward / lateral offsets and blocker checks against Town bounds, buildings, environment instances and the bus. The existing `ExpeditionCamera` remains in use and continues to follow `mission.squad_center()`.
